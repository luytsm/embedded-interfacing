# 3.2 Datatypes

Elke variabele in C/C++ heeft een **type**. Dat type bepaalt hoeveel
geheugen de variabele inneemt en welke waarden erin kunnen. Op een
microcontroller is dat geen detail: een ATmega328P (Arduino Nano) heeft
slechts 2 kB RAM, een ESP32 ongeveer 520 kB. Een verkeerd of onnodig groot
type kost dus al snel merkbaar geheugen, en een te klein type geeft foute
resultaten.

## 3.2.1 De basistypes

| Type        | Betekenis                           | Grootte op AVR (Nano) | Grootte op ESP32 |
| ----------- | ----------------------------------- | --------------------- | ---------------- |
| `bool`      | `true` of `false`                   | 1 byte                | 1 byte           |
| `char`      | één karakter (ASCII)                | 1 byte                | 1 byte           |
| `byte`      | getal van 0 tot 255 (Arduino-alias) | 1 byte                | 1 byte           |
| `int`       | geheel getal                        | **2 bytes**           | **4 bytes**      |
| `long`      | geheel getal                        | 4 bytes               | 4 bytes          |
| `long long` | groot geheel getal                  | 8 bytes               | 8 bytes          |
| `float`     | kommagetal                          | 4 bytes               | 4 bytes          |
| `double`    | kommagetal met dubbele precisie     | **4 bytes**           | **8 bytes**      |

Enkele toelichtingen bij deze types.

**bool**

Een `bool` kent maar twee waarden: `true` en `false`. In Arduino zijn `HIGH`
en `LOW` gewoon andere namen voor `1` en `0`, waardoor `HIGH`, `true` en `1`
onderling uitwisselbaar zijn, net als `LOW`, `false` en `0`.

**char en char[]**

Een `char` bevat één karakter, maar wordt intern opgeslagen als een
**getal** volgens de **ASCII-tabel**: de hoofdletter `'A'` is 65, de kleine
letter `'a'` is 97. Een reeks karakters, oftewel een **string** in C, is een
`char[]` (een *array* van karakters). Zo'n string wordt afgesloten met een
onzichtbaar nulkarakter `\0`, zodat het programma weet waar de tekst eindigt.
Het woord `"Geeks"` neemt daardoor 6 bytes in: vijf letters en het
afsluitende `\0`.

```cpp
char letter = 'A';                 // stored as the number 65
char greeting[] = "Hello";         // 'H','e','l','l','o','\0' -> 6 bytes
```

> **Let op:** `String` (met hoofdletter) is iets anders. Dat is geen type uit C
> maar een C++-klasse uit de Arduino core (de code staat in `WString.h` en
> `WString.cpp` in de core, zie 2.3.2). In dit vak wordt de `String`-klasse
> **zoveel mogelijk vermeden**. Een `char[]` is eenvoudiger, zuiniger en
> efficiënter te manipuleren met de standaardbibliotheek `string.h`, en is
> ook wat het ESP-IDF gebruikt. Zie 3.2.5 voor de reden.

**Gehele getallen: int, long, long long**

Gehele getallen worden opgeslagen als **2's-complement**, met een teken. Het
bereik hangt af van het aantal bytes. Voor een `int` van 4 bytes (ESP32) loopt
dat van -2.147.483.648 tot 2.147.483.647, voor een `int` van 2 bytes (Nano)
slechts van -32.768 tot 32.767. Een `long long` (8 bytes) gaat van
-9.223.372.036.854.775.808 tot 9.223.372.036.854.775.807. Met het voorvoegsel
`unsigned` valt het teken weg en verdubbelt het positieve bereik, bijvoorbeeld
`unsigned int` (0 tot 65.535 op een Nano).

**Kommagetallen: float en double**

Een `float` is een 32-bits kommagetal, met een bereik van ongeveer
3,4 × 10⁻³⁸ tot 3,4 × 10³⁸. Een `double` is een 64-bits kommagetal met een
veel groter bereik, ongeveer 1,7 × 10⁻³⁰⁸ tot 1,7 × 10³⁰⁸. Op een 8-bits
AVR wordt `double` echter teruggebracht tot dezelfde grootte als `float`,
omdat zo'n chip geen 64-bits berekeningen in één keer kan uitvoeren.

De ESP32 ondersteunt wel een volwaardige 64-bits `double`, maar de
floating-point hardware van de ESP32 werkt enkel met 32 bits. Berekeningen met
`double` gebeuren daardoor in software en zijn merkbaar trager dan met
`float`. Waar de extra precisie niet nodig is, is `float` op de ESP32 dus de
betere keuze.

## 3.2.2 Types met vaste grootte

De tabel hierboven toont het probleem: `int` is op een Nano 2 bytes groot en
op een ESP32 4 bytes. Dezelfde code kan dus op twee boards tot verschillende
resultaten leiden. Voor code die overal hetzelfde moet werken, bestaan daarom
**types met vaste grootte**, gedefinieerd in de header `stdint.h`:

| Type       | Grootte | Bereik                                                   |
| ---------- | ------- | -------------------------------------------------------- |
| `uint8_t`  | 1 byte  | 0 tot 255                                                |
| `int8_t`   | 1 byte  | -128 tot 127                                             |
| `uint16_t` | 2 bytes | 0 tot 65.535                                             |
| `int16_t`  | 2 bytes | -32.768 tot 32.767                                       |
| `uint32_t` | 4 bytes | 0 tot 4.294.967.295                                      |
| `int32_t`  | 4 bytes | -2.147.483.648 tot 2.147.483.647                         |
| `uint64_t` | 8 bytes | 0 tot 18.446.744.073.709.551.615                         |
| `int64_t`  | 8 bytes | -9.223.372.036.854.775.808 tot 9.223.372.036.854.775.807 |

De `u` staat voor *unsigned* (zonder teken), het getal achteraan is het aantal
bits. In de Arduino IDE zijn deze types automatisch beschikbaar. Ze zijn ook
al tegengekomen: de `digitalWrite(uint8_t pin, uint8_t val)` uit 2.3.2 gebruikt
ze in beide cores. In het ESP-IDF zijn ze de standaard, en ook in dit vak
worden ze regelmatig gebruikt.

## 3.2.3 De grootte zelf opvragen

Met `sizeof()` kan op het eigen board gecontroleerd worden hoe groot een type
effectief is. De uitvoer verschijnt in de Serial Monitor (zie 2.2):

```cpp
void setup() {
  Serial.begin(115200);
  Serial.print("int: ");     Serial.println(sizeof(int));
  Serial.print("long: ");    Serial.println(sizeof(long));
  Serial.print("float: ");   Serial.println(sizeof(float));
  Serial.print("double: ");  Serial.println(sizeof(double));
}

void loop() {}
```

Op een ESP32 geeft dit 4, 4, 4 en 8, op een Nano 2, 4, 4 en 4.

## 3.2.4 Let op: overloop

Een variabele kan enkel waarden binnen haar bereik bevatten. Wordt dat
bereik overschreden, dan loopt de variabele **over** en begint ze aan de
andere kant opnieuw:

```cpp
uint8_t counter = 255;   // maximum value of an 8-bit unsigned number
counter++;               // wraps around to 0
```

Dit is een klassieke bron van fouten, zeker bij tellers en tijdmetingen. Een
`int` van 2 bytes loopt op een Nano al over na 32.767, terwijl dezelfde code op
een ESP32 nog ruim voldoende marge heeft. De keuze van het juiste type
(en het gebruik van types met vaste grootte) voorkomt zulke verrassingen.

Meer informatie over de groottes van types op verschillende platformen is te
vinden op:

- [luisllamas.es — Variable sizes in ESP32, Arduino, Raspberry Pi, Windows and Linux](https://www.luisllamas.es/en/variable-sizes-in-esp32-arduino-raspberry-pi-windows-and-linux/)
- [learn.microsoft.com — Data type ranges](https://learn.microsoft.com/en-us/cpp/cpp/data-type-ranges?view=msvc-170)

## 3.2.5 String vermijden: char[] en string.h

De Arduino-klasse `String` is aantrekkelijk omdat ze zich gedraagt zoals
tekst in hogere talen: met `+` en `+=` kunnen strings eenvoudig aan elkaar
gekoppeld worden. Achter die eenvoud zit echter heel wat werk dat op een
microcontroller niet gratis is.

**Waarom een `String` een probleem kan zijn**

- Een `String` beheert haar geheugen **dynamisch, op de heap**. Wordt de tekst
  langer, dan vraagt de klasse intern een groter stuk geheugen aan
  (`realloc()` in `WString.cpp`), kopieert de bestaande tekst en geeft het
  oude stuk terug. Dat kost bij elke aanpassing tijd.
- Door het herhaaldelijk aanvragen en vrijgeven van geheugenblokken van
  wisselende grootte raakt de heap na verloop van tijd **gefragmenteerd**: er
  is in totaal nog voldoende vrij geheugen, maar niet meer in één stuk. Een
  embedded toestel draait vaak dagen of weken aan een stuk, waardoor zo'n
  probleem pas na lange tijd optreedt en moeilijk te reproduceren is. Op een
  Nano met 2 kB RAM is dit een reëel risico.
- Het geheugengebruik is **niet voorspelbaar**: het hangt af van wat er
  tijdens de uitvoering gebeurt, niet van wat er in de code staat.

Een `char[]` heeft daar geen last van. Haar grootte ligt bij het compileren
vast, ze staat in statisch geheugen of op de stack, en er wordt niets
aangevraagd of vrijgegeven. Bovendien biedt de standaardbibliotheek
**`string.h`** een set functies die rechtstreeks op zulke arrays werken, in
plain C, en dus ook beschikbaar zijn in het ESP-IDF:

| Functie                                        | Doet                                            |
| ---------------------------------------------- | ----------------------------------------------- |
| `strlen(s)`                                    | lengte van de tekst (zonder `\0`)               |
| `strcpy(dst, src)`                             | tekst kopiëren                                  |
| `strcat(dst, src)`                             | tekst achteraan toevoegen                       |
| `strcmp(a, b)`                                 | twee teksten vergelijken (0 als ze gelijk zijn) |
| `strncpy(dst, src, n)`, `strncat(dst, src, n)` | idem, met een maximum aantal tekens             |
| `memcpy(dst, src, n)`, `memset(dst, value, n)` | een blok geheugen kopiëren of vullen            |

Daar staat één belangrijk nadeel tegenover: de programmeur moet zelf zorgen
dat de array **groot genoeg** is. Schrijven voorbij het einde (*buffer
overflow*) geeft geen foutmelding maar overschrijft ander geheugen. De
varianten met een maximum (`strncat()`, `strncpy()`) en `snprintf()` bieden
daartegen bescherming.
