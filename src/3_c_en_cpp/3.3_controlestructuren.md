# 3.3 Controlestructuren

Een programma voert niet altijd alle regels code na elkaar uit. Met
**controlestructuren** wordt bepaald welke code uitgevoerd wordt (**keuzes**)
en hoe vaak (**herhalingen**).

Voorwaarden worden opgebouwd met vergelijkings- en logische operatoren:

| Operator             | Betekenis                                                            |
| -------------------- | -------------------------------------------------------------------- |
| `==`, `!=`           | gelijk aan, niet gelijk aan                                          |
| `<`, `>`, `<=`, `>=` | kleiner dan, groter dan, kleiner of gelijk aan, groter of gelijk aan |
| `&&`                 | en (beide voorwaarden waar)                                          |
| `\|\|`               | of (minstens één voorwaarde waar)                                    |
| `!`                  | niet (keert een voorwaarde om)                                       |

> **Let op:** `=` en `==` zijn niet hetzelfde. `=` **kent een waarde toe**,
> `==` **vergelijkt**. `if (x = 5)` is geldige code die x op 5 zet en altijd
> waar is, en dus bijna nooit bedoeld. Dit is een klassieke bron van
> moeilijk te vinden fouten.

## 3.3.1 Keuzes

### if, else if en else

De meest gebruikte controlestructuur is het `if`-statement: een stuk code
wordt enkel uitgevoerd als aan een voorwaarde voldaan is.

```cpp
void loop() {
  int temperature = analogRead(sensor_pin);

  if (temperature > 3000) {
    Serial.println("too hot");
  } else if (temperature < 1000) {
    Serial.println("too cold");
  } else {
    Serial.println("just right");
  }
}
```

De voorwaarden worden van boven naar onder gecontroleerd. Zodra er één waar is,
wordt enkel dat blok uitgevoerd en worden de overige overgeslagen. `else`
vangt alles op wat niet aan de voorgaande voorwaarden voldeed en is optioneel.

### Guard clause

Het **nesten** van `if`-statements (een `if` binnen een `if`) doet de
leesbaarheid snel afnemen. Uit ervaring blijkt dat de meeste problemen bij
het schrijven van code terug te voeren zijn op sterk geneste `if`-structuren.
Een sterke techniek daartegen is de **guard clause**: zodra een voorwaarde
voldaan is, wordt de functie onmiddellijk verlaten met `return`, in plaats
van de rest van de logica in `else`-blokken te steken.

**Zonder guard clauses (sterk genest):**

```cpp
int get_led_brightness(bool is_enabled, bool is_night_mode, int light_level) {
  int result;

  if (!is_enabled) {
    result = 0;
  } else {
    if (is_night_mode) {
      result = 20;
    } else {
      if (light_level < 500) {
        result = 255;
      } else {
        result = 100;
      }
    }
  }

  return result;
}
```

**Met guard clauses:**

```cpp
int get_led_brightness(bool is_enabled, bool is_night_mode, int light_level) {
  if (!is_enabled) {
    return 0;
  }
  if (is_night_mode) {
    return 20;
  }
  if (light_level < 500) {
    return 255;
  }
  return 100;
}
```

Beide functies doen exact hetzelfde, maar de tweede leest van boven naar
onder: elk speciaal geval wordt afgehandeld en de rest van de functie kan
ervan uitgaan dat dat geval niet meer aan de orde is. Guard clauses
consequent toepassen is een goede gewoonte om van bij het begin aan te leren.

### switch-case

Wanneer **één variabele** met meerdere mogelijke waarden vergeleken wordt, is
een `switch`-`case` vaak overzichtelijker dan een lange reeks `else if`'s.
Het volgende voorbeeld leest een commando van de Serial Monitor (zie 2.2.2):

```cpp
void loop() {
  if (Serial.available() > 0) {
    char command = Serial.read();

    switch (command) {
      case 'a':
        digitalWrite(LED_BUILTIN, HIGH);
        break;
      case 'u':
        digitalWrite(LED_BUILTIN, LOW);
        break;
      case '\n':
      case '\r':
        break;    // ignore line endings sent by the Serial Monitor
      default:
        Serial.println("unknown command");
        break;
    }
  }
}
```

- Elke `case` eindigt met een **`break;`**. Zonder `break` loopt de uitvoering
  door in de volgende `case` (*fall-through*), een klassieke fout. Dat kan
  soms gewenst zijn, zoals bij `'\n'` en `'\r'` hierboven, waar twee labels
  hetzelfde blok delen.
- `default` wordt uitgevoerd als geen enkele `case` past. Het is optioneel,
  maar een goede gewoonte.
- Een `switch` werkt enkel met **gehele waarden** (zoals `int`, `char` of een
  `enum`), niet met kommagetallen of strings.


## 3.3.2 Herhalingen

### for

Een `for`-lus wordt gebruikt wanneer het **aantal herhalingen op voorhand
bekend** is. Tussen de haakjes staan drie delen: de startwaarde, de
voorwaarde om door te gaan, en wat na elke ronde gebeurt.

```cpp
void loop() {
  for (int i = 0; i < 5; i++) {   // runs 5 times: i = 0, 1, 2, 3, 4
    digitalWrite(LED_BUILTIN, HIGH);
    delay(200);
    digitalWrite(LED_BUILTIN, LOW);
    delay(200);
  }
  delay(2000);
}
```

Hier knippert de led vijf keer, waarna twee seconden gewacht wordt. Merk op
dat de teller van 0 begint: `i < 5` geeft dus vijf rondes.

### while

Een `while`-lus herhaalt zolang een voorwaarde waar is, en de voorwaarde wordt
**vóór** elke ronde gecontroleerd. Dat is geschikt wanneer het aantal
herhalingen niet op voorhand bekend is. Een typisch voorbeeld is het
leegmaken van de binnenkomende seriële data:

```cpp
void loop() {
  while (Serial.available() > 0) {
    char received_char = Serial.read();
    Serial.print(received_char);
  }
}
```

### do-while

Bij een `do`-`while` wordt de voorwaarde **na** elke ronde gecontroleerd. Het
blok wordt daardoor **minstens één keer** uitgevoerd, ook als de voorwaarde
van bij het begin niet waar is:

```cpp
int attempts = 0;

do {
  Serial.println("trying to connect...");
  attempts++;
} while (attempts < 3);
```

### break en continue

- `break;` verlaat de lus onmiddellijk (zoals ook bij `switch`).
- `continue;` slaat de rest van de huidige ronde over en gaat naar de volgende.

### Lussen in embedded code

Op een computer is een eindeloze lus meestal een fout. Op een microcontroller
is dat anders: `loop()` is zelf al een eindeloze lus, want een microcontroller
moet blijven werken zolang hij voeding heeft. Lussen in een sketch moeten
daarentegen wel eindigen. Een `while` waarvan de voorwaarde nooit onwaar
wordt, houdt de rest van het programma tegen, en het board lijkt vast te
zitten. Op dezelfde manier houdt een lange `delay()` binnen een lus de rest
van het programma tegen (zie de non-blocking aanpak die later aan bod komt).
