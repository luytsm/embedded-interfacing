# 3.1 Arduino is geen programmeertaal

Er wordt vaak gesproken over "programmeren in Arduino" of over "de
Arduino-taal". In de volksmond is dat begrijpelijk, maar technisch klopt het
niet: **Arduino is geen programmeertaal**. Voor de rest van dit vak is het
belangrijk om dat verschil scherp te hebben, want het bepaalt wat er in
Arduino-code mogelijk is en wat er verandert wanneer later overgeschakeld
wordt naar het ESP-IDF.

## 3.1.1 Wat Arduino wel is

Arduino is, softwarematig gezien, een **uitbreiding bovenop een bestaande
taal**: een verzameling extra libraries (de Arduino core en de bijhorende
bibliotheken, zie 2.3) samen met een IDE die het compileren en uploaden
automatiseert. Die libraries zijn zelf geschreven in **C en C++**. De taal
waarin een sketch effectief geschreven wordt, is dus **C++**. Zoals in 1.1.3
besproken, wordt een sketch eerst door een voorverwerkingsstap gehaald
(onder meer om `#include <Arduino.h>` toe te voegen) en daarna als gewone
C++-code gecompileerd.

Dat is ook in gewone sketchcode te herkennen:

```cpp
void setup() {
  Serial.begin(115200);           // C++: a method called on an object
  pinMode(LED_BUILTIN, OUTPUT);   // C-style: a plain function
}
```

- `Serial` is een **object** van de klasse `HardwareSerial`. De schrijfwijze
  `object.methode()` bestaat enkel in C++. De klasse zelf staat in het
  bestand `HardwareSerial.cpp` in de core.
- `pinMode()` en `digitalWrite()` zijn **gewone functies**, geschreven in C.

Een core bestaat dus uit een mengeling van C- en C++-bestanden. Daaruit volgt
ook dat alles wat in C/C++ mogelijk is, in een sketch mogelijk is:
pointers, structs, enums, klassen, enzovoort. Arduino voegt daar vooral
handige functies en constanten aan toe (`delay()`, `HIGH`, `LOW`, ...), maar
neemt niets weg. Een refresher van de Arduino-code is daarom eigenlijk een
refresher van C/C++, met datatypes (3.2) en controlestructuren (3.3) als
bouwstenen.

## 3.1.2 Het ESP-IDF: C

Het **ESP-IDF** is geschreven in **C**. Er is geen Arduino-laag, en dus ook
geen `setup()` en `loop()`: de programmeur schrijft zelf een functie
`app_main()` die één keer opgeroepen wordt bij het opstarten. Wie een
eindeloze lus nodig heeft, moet die zelf voorzien. Dat is dezelfde situatie
als bij het voorbeeld zonder Arduino core in 1.1.3, waar enkel een
`main()` met een eigen `while (1)` bestond.

```c
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "esp_log.h"

static const char *tag = "main";

void app_main(void) {
  while (1) {
    ESP_LOGI(tag, "hello from esp-idf");
    vTaskDelay(pdMS_TO_TICKS(1000));   // wait 1000 ms
  }
}
```

De details van dit voorbeeld komen later in het vak aan bod. Belangrijk is
hier enkel de vaststelling dat dit **gewone C** is: geen objecten, geen
`Serial.print()`, maar losse functies zoals `ESP_LOGI()` (het logsysteem uit
2.3.2) en `vTaskDelay()`.

**C++ is echter niet uitgesloten.** De compiler achter het ESP-IDF
ondersteunt ook C++, en een bronbestand kan gewoon de extensie `.cpp`
krijgen. Het ESP-IDF zelf is een C-omgeving en roept `app_main()` op via zijn
C-naam. Een C++-compiler past namen echter aan (*name mangling*), waardoor
die oproep niet meer zou lukken. Daarom wordt `app_main()` in een `.cpp`-bestand
voorzien van `extern "C"`:

```cpp
extern "C" void app_main(void) {
  // from here on, classes and other C++ features can be used
}
```
