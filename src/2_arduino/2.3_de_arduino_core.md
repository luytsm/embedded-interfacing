# 2.3 De Arduino core

Zoals in 1.1.3 besproken, is de **Arduino core** de abstractielaag die
functies als `pinMode()`, `digitalWrite()` en `delay()` vertaalt naar de
registers van één specifieke microcontrollerfamilie. Daaruit volgt een
belangrijk gegeven: **elke microcontrollerfamilie heeft zijn eigen core**. De
`digitalWrite()` van een ATmega328P (Arduino Nano) ziet er intern helemaal
anders uit dan die van een ESP32, ook al is de functieaanroep in de sketch
identiek.

In de Arduino IDE komt dit tot uiting in de **Boards Manager**. Daar worden de
cores beheerd (geïnstalleerd, bijgewerkt of verwijderd). Een core bevat
doorgaans:

- de implementatie van alle Arduino-functies voor die microcontrollerfamilie;
- de **toolchain**: de compiler en bijhorende hulpprogramma's om code voor die
  familie te bouwen;
- de definitie van de beschikbare **boards**, inclusief hun pinnummering.

## 2.3.1 De ESP32-core is niet standaard aanwezig

Bij een verse installatie van de Arduino IDE zijn enkel de cores voor de
officiële Arduino-boards beschikbaar. De **Arduino core voor de ESP32** is
**niet standaard geïnstalleerd**, en zonder die core staat de FireBeetle 2
niet in de lijst van boards. Zoals in 1.1.1 aangehaald, wordt deze core
onderhouden door Espressif zelf, en niet door Arduino.

Vroeger vergde dit een manuele ingreep: een extra URL moest eerst toegevoegd
worden aan de voorkeuren van de IDE. In de huidige versies van de Arduino IDE
is dat niet meer nodig. De core kan rechtstreeks via de Boards Manager
gedownload worden.

**Stap 1: de core installeren**

1. Open de **Boards Manager** in de zijbalk.
2. Zoek op `esp32`.
3. Installeer **esp32 by Espressif Systems**.

> **Let op:** in de zoekresultaten staat ook **Arduino ESP32 Boards**. Dat
> pakket is de core voor de eigen ESP32-boards van Arduino (zoals de Nano
> ESP32) en is **niet** de juiste voor dit vak. Kies dus zeker het pakket van
> Espressif Systems.

> **Let op:** deze installatie is geen snelle operatie. Naast de
> Arduino-functies wordt ook de volledige toolchain voor de ESP32 gedownload,
> wat al gauw enkele honderden megabytes bedraagt. Best gebeurt dit dus op
> voorhand met een goede internetverbinding, en niet op het moment dat het
> board effectief nodig is.

**Stap 2: het board selecteren**

Na de installatie kan het board gekozen worden via *Tools > Board >
esp32 > FireBeetle 2 ESP32-E*, of via de board-dropdown in de werkbalk.
Vervolgens wordt de **poort** gekozen, en is het board klaar om geprogrammeerd
te worden.

## 2.3.2 Onder de motorkap: digitalWrite() in de ESP32-core

Een core is geen zwarte doos. De volledige broncode staat na de installatie
gewoon op de computer, en is ook te bekijken op GitHub
([espressif/arduino-esp32](https://github.com/espressif/arduino-esp32)). Voor
wie benieuwd is hoe een functie als `digitalWrite()` effectief werkt, is dat
een leerrijk vertrekpunt. Op Windows staat de core standaard hier:

```text
%LOCALAPPDATA%\Arduino15\packages\esp32\hardware\esp32\<version>\
```

De GPIO-functies zitten in `cores\esp32\esp32-hal-gpio.c`. Daar staat de
implementatie van `digitalWrite()`,weergegeven (versie 3.3.12,
latere versies kunnen afwijken):

```c
extern void ARDUINO_ISR_ATTR __digitalWrite(uint8_t pin, uint8_t val) {
#ifdef RGB_BUILTIN
  if (pin == RGB_BUILTIN) {
    //use RMT to set all channels on/off
    RGB_BUILTIN_storage = val;
    const uint8_t comm_val = val != 0 ? RGB_BRIGHTNESS : 0;
    rgbLedWrite(RGB_BUILTIN, comm_val, comm_val, comm_val);
    return;
  }
#endif  // RGB_BUILTIN
  if (perimanGetPinBus(pin, ESP32_BUS_TYPE_GPIO) != NULL) {
    gpio_set_level((gpio_num_t)pin, val);
  } else {
    log_e("IO %u is not set as GPIO. Execute digitalMode(%u, OUTPUT) first.", pin, pin);
  }
}
```

Wat opvalt:

- De eigenlijke actie is `gpio_set_level()`. Dat is geen Arduino-functie, maar
  een functie uit het **ESP-IDF**. De Arduino core is dus effectief een dun
  laagje bovenop de functionaliteit van Espressif (zie 3.1).
- Vóór de pin geschakeld wordt, controleert de core eerst of de pin wel als
  GPIO in gebruik is. Dat is nuttige veiligheid voor beginners (een duidelijke
  foutmelding in de Serial Monitor in plaats van een stille fout), maar het is
  ook extra werk bij elke aanroep. Dit is dezelfde soort overhead als die
  waarover in 1.1.3 gesproken werd.

### Ter vergelijking: digitalWrite() in de AVR-core

Om te zien hoe verschillend twee cores dezelfde functie kunnen invullen, kan
de implementatie naast die van de AVR-core gelegd worden. Die core hoort bij
de klassieke Arduino-boards (zoals de Nano V3.0 met ATmega328P uit 1.1) en
staat standaard bij de IDE. Op Windows:

```text
%LOCALAPPDATA%\Arduino15\packages\arduino\hardware\avr\<version>\cores\arduino\wiring_digital.c
```

Dit is de implementatie van `digitalWrite()` in versie 1.8.7 van die core:

```c
void digitalWrite(uint8_t pin, uint8_t val) {
  uint8_t timer = digitalPinToTimer(pin);
  uint8_t bit = digitalPinToBitMask(pin);
  uint8_t port = digitalPinToPort(pin);
  volatile uint8_t *out;

  if (port == NOT_A_PIN) return;

  // If the pin that support PWM output, we need to turn it off
  // before doing a digital write.
  if (timer != NOT_ON_TIMER) turnOffPWM(timer);

  out = portOutputRegister(port);

  uint8_t oldSREG = SREG;
  cli();

  if (val == LOW) {
    *out &= ~bit;
  } else {
    *out |= bit;
  }

  SREG = oldSREG;
}
```

Wat hier opvalt, in vergelijking met de ESP32-core:

- **Het pinnummer wordt eerst vertaald.** Uit het pinnummer worden de
  bijhorende *poort* (bijvoorbeeld PORTB), de *bitmask* (welk bit in dat
  register) en eventueel een *timer* opgezocht. Dat is het opzoekwerk dat in
  1.1.3 werd aangehaald als reden waarom `digitalWrite()` trager is dan
  rechtstreeks naar `PORTB` schrijven.
- **De pin wordt ook hier eerst gecontroleerd en voorbereid.** Bij een
  ongeldige pin stopt de functie (`NOT_A_PIN`), en als de pin een PWM-uitgang
  is, wordt die PWM eerst uitgeschakeld (`turnOffPWM()`).
- **De eigenlijke actie is een directe registerschrijfactie.** De regels
  `*out &= ~bit` en `*out |= bit` zetten het bit in het `PORTx`-register op 0
  of 1, exact zoals in het voorbeeld zonder Arduino core in 1.1.3. Er is hier
  geen tussenliggend framework: de core spreekt rechtstreeks de hardware aan.
- **Interrupts worden kort uitgeschakeld** (`cli()`), zodat het aanpassen van
  het register niet halverwege onderbroken kan worden. Nadien wordt de vorige
  toestand hersteld (`SREG`).

Het verschil met de ESP32-core zit dus in het **laatste stukje**: de AVR-core
schrijft zelf naar het register, terwijl de ESP32-core die taak doorgeeft aan
een functie van het ESP-IDF (`gpio_set_level()`). In beide gevallen ziet de
sketch er hetzelfde uit: `digitalWrite(pin, HIGH)`. Dat is precies de
meerwaarde van een core: dezelfde code, op verschillende hardware.

### Nog een verschil: logging

In de ESP32-versie van `digitalWrite()` stond een regel die in de AVR-versie
volledig ontbreekt: `log_e("IO %u is not set as GPIO. ...")`. Dat is geen
`Serial.print()`, maar een **logfunctie**. De ESP32 heeft logging diep in het
framework ingebouwd, met de **log levels** van het ESP-IDF:

| Level             | Betekenis                                           |
| ----------------- | --------------------------------------------------- |
| **Error** (`E`)   | er is iets misgelopen                               |
| **Warning** (`W`) | er is iets verdachts, maar het programma kan verder |
| **Info** (`I`)    | normale werking, bijvoorbeeld "verbonden met WiFi"  |
| **Debug** (`D`)   | details voor wie een probleem zoekt                 |
| **Verbose** (`V`) | alles, ook de kleinste details                      |

Elke logregel krijgt automatisch het level, een tijdstip en een **tag**
(de naam van het onderdeel dat de melding stuurt) mee. Het grote voordeel
zit in het **filteren**: per level, en zelfs per tag, kan bepaald worden welke
meldingen effectief getoond worden. Zo kunnen de meldingen van onderdelen die
al werken uitgeschakeld worden, zodat enkel die van het onderdeel waaraan
gewerkt wordt overblijven.

Ook in de Arduino IDE kan dit ingesteld worden, via *Tools > Core Debug
Level*. Die optie verschijnt zodra een board geselecteerd is dat de
ESP32-core gebruikt. Er zijn zes niveaus om uit te kiezen:

- **None**: de core print helemaal niets. Dit is de standaardinstelling.
- **Error**: enkel echte fouten, zoals de melding uit `digitalWrite()` bij
  een pin die niet als GPIO ingesteld is.
- **Warn**: fouten én waarschuwingen, voor situaties die verdacht zijn maar
  het programma niet stoppen.
- **Info**: daarbovenop ook meldingen over de normale werking, zoals het
  verbinden met een WiFi-netwerk.
- **Debug**: extra details over wat de core intern doet, handig bij het
  zoeken naar een fout.
- **Verbose**: alles, tot de kleinste details. Dit geeft snel heel veel
  output.

Elk level toont ook alle meldingen van de levels erboven: wie **Info** kiest,
krijgt dus ook de errors en warnings te zien. Die meldingen verschijnen gewoon
in de **Serial Monitor**, tussen de eigen output van de sketch. Loopt er iets
mis zonder duidelijke reden, dan loont het de moeite om het level tijdelijk op
**Debug** of **Verbose** te zetten: vaak meldt de core dan zelf waar het
probleem zit.

In de code zelf ziet logging er zo uit:

```c
static const char *tag = "distance_sensor";

void read_distance() {
  ESP_LOGD(tag, "starting measurement");    // debug: detail
  ESP_LOGI(tag, "distance: %d mm", 245);    // info: normal operation
  ESP_LOGE(tag, "sensor not responding");   // error: something went wrong
}

// at startup: only show warnings and errors for this tag
esp_log_level_set("distance_sensor", ESP_LOG_WARN);
```

Bij de klassieke Arduino-boards (zoals de Nano) bestaat enkel
`Serial.print()`. Dat is heel eenvoudig voor snel en ruw debuggen: gewoon
waarden uitprinten. Maar alles wordt even luid getoond, en de printregels moeten
achteraf met de hand verwijderd of uitgecommentarieerd worden. In het
ESP32-framework kan sneller naar de oorzaak van een fout gezocht worden.

> **Opinie:** dit is voor mij een van de grootste redenen om fan te zijn van
> het ESP32-ecosysteem: logging is er heel grondig in verweven, en bij het
> zoeken naar fouten scheelt dat enorm veel tijd.
