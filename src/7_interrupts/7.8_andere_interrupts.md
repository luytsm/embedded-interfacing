# 7.8 Andere interrupts

Tot hier ging het telkens over een interrupt op een **GPIO**: een flank of een
niveau op een pin. Elke peripheral van een microcontroller heeft echter zijn
eigen **interruptbronnen** (*interrupt sources*): de UART wanneer er bytes
binnen zijn, de I²C-peripheral wanneer een transfer klaar is, een teller
wanneer hij een ingestelde waarde bereikt.

Bij die peripherals schrijft het programma de ISR meestal niet zelf. De
**driver** (in de Arduino core of in het ESP-IDF) installeert de ISR, handelt
de hardware af, en geeft het programma een seintje via een **callback**: een
functie uit de sketch die de driver oproept. Bij elke callback is daarom één
vraag belangrijk: wordt ze opgeroepen vanuit een **ISR**, of vanuit een
**taak**?

- **Vanuit een ISR**: alle regels uit [7.3.4](./7.3_gpio_interrupts_in_de_arduino_core.md#734-een-isr-declareren) en [7.5](./7.5_de_ideale_isr.md) gelden. De callback is
  kort, krijgt `ARDUINO_ISR_ATTR`, en gebruikt geen `Serial` of `delay()`.
- **Vanuit een taak**: de callback loopt in een FreeRTOS-taak, net zoals
  `loop()` in de taak `loopTask` loopt (zie [7.1.5](./7.1_de_superloop.md#715-een-alternatief-een-rtos)). Ze is dus geen ISR, en
  `Serial` en `delay()` zijn toegelaten. Toch blijft ook zo'n callback best
  kort:
  - zolang ze loopt, verwerkt de driver geen nieuwe meldingen;
  - de taak loopt naast `loop()`, mogelijk op de andere core van de ESP32.
    Voor variabelen die de callback en `loop()` delen, gelden dezelfde regels
    als in [7.4](./7.4_gedeelde_variabelen_en_volatile.md).

Een overzicht van de interrupts in deze sectie:

| Peripheral    | Callback in de sketch                  | Opgeroepen vanuit | Sectie                     |
| ------------- | -------------------------------------- | ----------------- | -------------------------- |
| GPIO          | `attachInterrupt()`                    | ISR               | [7.3](./7.3_gpio_interrupts_in_de_arduino_core.md)    |
| UART          | `onReceive()`, `onReceiveError()`      | taak              | [7.8.1](#781-uart)         |
| I²C (slave)   | `Wire.onReceive()`, `Wire.onRequest()` | taak              | [7.8.2](#782-i²c)           |
| Timer         | `timerAttachInterrupt()`               | ISR               | [7.8.3](#783-tellers-timers-en-de-pulse-counter) |
| Pulse counter | `on_reach` (ESP-IDF)                   | ISR               | [7.8.3](#783-tellers-timers-en-de-pulse-counter) |

Tot slot blikt [7.8.4](#784-historiek-ext_int-en-pin_change-op-de-avr) terug naar de Arduino Nano: hoe de ATmega328P
interrupts op een pin regelt, en waarom `attachInterrupt()` daar maar op twee
pinnen werkt.

## 7.8.1 UART

### De interruptbronnen van een UART

Een UART kan bij heel wat gebeurtenissen een interrupt geven. Een selectie
van de interruptbronnen van de UART in de ESP32:

| Interrupt      | Treedt op wanneer ...                                                         |
| -------------- | ----------------------------------------------------------------------------- |
| `RXFIFO_FULL`  | de ontvangst-FIFO een ingesteld aantal bytes bevat                            |
| `RXFIFO_TOUT`  | er na een ontvangen byte een tijd lang niets meer binnenkomt (*RX timeout*)   |
| `TXFIFO_EMPTY` | de zend-FIFO bijna leeg is, en dus aangevuld kan worden                       |
| `RXFIFO_OVF`   | de ontvangst-FIFO overloopt: er gaan bytes verloren                           |
| `FRAM_ERR`     | er geen geldige stop bit ontvangen wordt (zie [5.2.5](../5_seriele_communicatie/5.2_uart.md#525-synchronisatie-start-bit-en-stop-bit)), bijvoorbeeld bij een verkeerde baudrate |
| `PARITY_ERR`   | de pariteit niet klopt (zie [5.2.6](../5_seriele_communicatie/5.2_uart.md#526-foutcontrole-pariteit))                                    |
| `BRK_DET`      | de lijn langer dan één frame laag blijft (*break*)                            |

De UART-driver van het ESP-IDF gebruikt die interrupts in drie stappen:

1. Bij `RXFIFO_FULL` en `RXFIFO_TOUT` verplaatst de **ISR van de driver** de
   bytes uit de hardware-FIFO van 128 bytes naar de ontvangstbuffer (zie
   [5.5.3](../5_seriele_communicatie/5.5_serial_in_de_arduino_core.md#de-ontvangstbuffer-is-beperkt)). Daarom ziet `available()` de bytes, zonder dat de sketch er
   iets voor hoeft te doen.
2. Dezelfde ISR plaatst een **event** in een wachtrij: data ontvangen,
   ontvangstbuffer vol, FIFO overgelopen, framefout, ...
3. Zodra de sketch een callback instelt, start de ESP32-core voor die UART
   een **FreeRTOS-taak**, `uart_event_task`. Die wacht op de events, en roept
   de callbacks uit de sketch op.

### onReceive() en onReceiveError()

In `HardwareSerial` (ESP32-core, versie 3.3) staan daarvoor twee functies:

```cpp
void onReceive(OnReceiveCb function, bool onlyOnTimeout = false);
void onReceiveError(OnReceiveErrorCb function);
```

- `onReceive()` geeft een callback wanneer er bytes in de ontvangstbuffer
  terechtkomen. De tweede parameter bepaalt wanneer:
  - `false` (de standaardwaarde): telkens de driver bytes uit de FIFO naar de
    ontvangstbuffer verplaatst. Een lang bericht komt dus in stukken binnen:
    bij lage baudrates zelfs byte per byte, bij hoge baudrates per 120 bytes.
  - `true`: enkel na een **pauze** in de data (*RX timeout*). Een volledig
    bericht staat dan in één keer in de buffer.
- Hoe lang die pauze moet duren, stelt `setRxTimeout()` in, in **symbolen**:
  de tijd van één frame (zie [5.2.7](../5_seriele_communicatie/5.2_uart.md#527-het-volledige-frame)), 10 bits bij `SERIAL_8N1`. De ESP32-core
  gebruikt standaard 1 symbool. Het maximum bij `SERIAL_8N1` is 101 symbolen,
  maar op de ESP32 enkel met de **APB-klok** als klokbron van de UART. Onder
  250000 baud kiest de core standaard de klok REF_TICK, en daarmee is de RX
  timeout beperkt tot 1 symbool. `setClockSource()`, vóór `begin()`, kiest een
  andere klokbron.
- `onReceiveError()` geeft een callback bij een fout, met het soort fout als
  parameter: `UART_BUFFER_FULL_ERROR` (de ontvangstbuffer zit vol),
  `UART_FIFO_OVF_ERROR`, `UART_FRAME_ERROR`, `UART_PARITY_ERROR` of
  `UART_BREAK_ERROR`.

### Een GPS-module

De GPS-module uit [5.5.5](../5_seriele_communicatie/5.5_serial_in_de_arduino_core.md#555-een-tweede-uart-gebruiken) stuurt elke seconde een reeks NMEA-regels kort na
elkaar, en is daarna stil tot de volgende seconde. Met
`onReceive(..., true)` en een RX timeout van 100 symbolen (aan 9600 baud
ongeveer 104 ms) volgt er **één callback per seconde**: op het moment dat
alle regels van die seconde binnen zijn.

```cpp
const uint8_t GPS_RX_PIN = 35;               // A3, connect TX of the GPS module
const uint8_t GPS_TX_PIN = 26;               // D3, connect RX of the GPS module
const unsigned long GPS_BAUD_RATE = 9600;    // default baud rate of most GPS modules
const size_t GPS_RX_BUFFER_SIZE = 1024;      // all NMEA lines of one second must fit
const uint8_t GPS_RX_TIMEOUT_SYMBOLS = 100;  // about 104 ms of silence at 9600 baud

HardwareSerial gps_serial(2);  // UART2

volatile bool is_burst_received = false;  // flag: set by mark_burst_received()
volatile bool is_data_lost = false;       // flag: set by mark_receive_error()

void mark_burst_received() {
  is_burst_received = true;
}

void mark_receive_error(hardwareSerial_error_t error) {
  if (error == UART_BUFFER_FULL_ERROR || error == UART_FIFO_OVF_ERROR) {
    is_data_lost = true;
  }
}

void handle_burst() {
  if (!is_burst_received) {
    return;
  }
  is_burst_received = false;
  Serial.printf("--- %d bytes ---\n", gps_serial.available());
  while (gps_serial.available() > 0) {
    Serial.write(gps_serial.read());
  }
}

void handle_data_lost() {
  if (!is_data_lost) {
    return;
  }
  is_data_lost = false;
  Serial.println("GPS data lost");
}

void setup() {
  Serial.begin(115200);

  gps_serial.setRxBufferSize(GPS_RX_BUFFER_SIZE);  // before begin()
  gps_serial.setClockSource(UART_CLK_SRC_APB);     // allows a long RX timeout
  gps_serial.begin(GPS_BAUD_RATE, SERIAL_8N1, GPS_RX_PIN, GPS_TX_PIN);
  gps_serial.setRxTimeout(GPS_RX_TIMEOUT_SYMBOLS);
  gps_serial.onReceive(mark_burst_received, true);  // true: only after a pause
  gps_serial.onReceiveError(mark_receive_error);
}

void loop() {
  handle_burst();
  handle_data_lost();
}
```

Wat opvalt:

- **De callbacks zijn geen ISR's.** Ze lopen in `uart_event_task`, en hebben
  dus geen `ARDUINO_ISR_ATTR` en geen suffix `_isr`. Toch volgen ze het
  patroon uit [7.6](./7.6_vlaggen.md): de callback zet enkel een vlag, `loop()` doet het werk. Zo
  weet `loop()` wanneer alle regels van een seconde in de buffer staan.
- **De vlaggen zijn `volatile`.** `uart_event_task` en `loopTask` kunnen op
  verschillende cores lopen. Een `bool` wordt op de ESP32 in één instructie
  gelezen of geschreven, dus gelden dezelfde afspraken als bij een vlag uit
  een ISR (zie [7.6.1](./7.6_vlaggen.md#761-het-principe)).
- **Eerst de klokbron, dan `begin()`.** Zonder `setClockSource()` faalt
  `setRxTimeout(100)` op de ESP32, en blijft de RX timeout 1 symbool: dan
  volgt er een callback bij elke korte pauze tussen twee regels.
- **De ontvangstbuffer is groter gemaakt.** Met `true` als tweede parameter
  leest niemand de buffer uit vóór de pauze: alle regels van één seconde
  moeten erin passen. Aan 9600 baud zijn dat hoogstens 960 bytes (zie
  [5.5.3](../5_seriele_communicatie/5.5_serial_in_de_arduino_core.md#de-ontvangstbuffer-is-beperkt)), de standaardbuffer van 256 bytes is te klein.
- **Verloren data wordt zichtbaar.** In [5.5.3](../5_seriele_communicatie/5.5_serial_in_de_arduino_core.md#de-ontvangstbuffer-is-beperkt) gingen bytes ongemerkt
  verloren wanneer de buffer volliep. `onReceiveError()` maakt dat zichtbaar.

> **Let op:** `serialEvent()` lijkt een callback bij ontvangen data, maar is
> het niet. Zowel de AVR-core als de ESP32-core roepen die functie gewoon op
> na elke doorloop van `loop()`, wanneer er bytes beschikbaar zijn. Dat is
> polling.

**Ter vergelijking, de Arduino Nano:** de AVR-core gebruikt één interrupt per
ontvangen byte (`USART_RX_vect`). De ISR zet de byte in de ontvangstbuffer
van 64 bytes. Een callback voor de sketch is er niet.

*Bron: `cores/esp32/HardwareSerial.h` en `HardwareSerial.cpp` in de ESP32-core
(versie 3.3.12), [Espressif, Arduino-ESP32, Serial](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/serial.html),
[Espressif, ESP-IDF, UART](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/uart.html)*

## 7.8.2 I²C

### De interrupts van de I²C-peripheral

Een I²C-transfer verloopt in stappen: startconditie, adres, ACK, data en
stopconditie (zie [6.6](../6_spi_en_i2c/6.6_het_i2c_protocol.md)). De I²C-peripheral voert die stappen zelf uit,
en geeft een interrupt wanneer er iets gebeurt:

- de transfer is klaar;
- een slave antwoordt met een NACK (zie [6.6.4](../6_spi_en_i2c/6.6_het_i2c_protocol.md#664-bevestiging-ack-en-nack));
- een andere master heeft de bus overgenomen (*arbitration lost*);
- de bus blijft te lang hangen (*timeout*), bijvoorbeeld door een slave die
  de klok te lang laag houdt (zie [clock stretching](../6_spi_en_i2c/6.6_het_i2c_protocol.md#clock-stretching)).

De ISR van de driver handelt die interrupts af. De **Wire**-bibliotheek, de
I²C-tegenhanger van `Serial`, wacht ondertussen: `Wire.endTransmission()` en
`Wire.requestFrom()` keren pas terug wanneer de ISR meldt dat de transfer klaar
is, of na een timeout van standaard 50 ms. Voor het programma is I²C dus een
functie die wacht, zoals de functies uit [5.5.4](../5_seriele_communicatie/5.5_serial_in_de_arduino_core.md#554-functies-die-wachten). Daarom hoort I²C niet
in een ISR (zie [7.5.2](./7.5_de_ideale_isr.md#752-wat-niet-in-een-isr-thuishoort)).

Is de ESP32 zelf een **slave**, dan geven `Wire.onReceive()` en
`Wire.onRequest()` een callback wanneer de master data stuurt of data
opvraagt. In de ESP32-core roept een taak (`i2c_slave_task`) die callbacks
op. In de AVR-core lopen ze in de ISR van de I²C-peripheral (`TWI_vect`): daar
gelden dus alle regels uit [7.5](./7.5_de_ideale_isr.md).

### Een INT-pin

In de praktijk komt een andere vorm vaker voor: een IC dat met een **extra
lijn** meldt dat er iets gebeurd is. Een meting staat klaar (*data ready*),
een grenswaarde is overschreden, een ingang is veranderd, ... Zonder die lijn
moet de master het IC blijven bevragen over de bus. Elke vraag is een
volledige transfer: aan 100 kHz duurt het lezen van één byte al gauw 0,2 ms.

Zo'n **INT-pin** heeft meestal dezelfde eigenschappen:

- **Open drain, actief laag** (zie [6.5.1](../6_spi_en_i2c/6.5_open_drain_en_pull_ups.md#651-open-drain)): het IC trekt de lijn laag
  wanneer het iets te melden heeft. Een pull-up-weerstand trekt de lijn
  anders hoog. De interne pull-up van de ESP32 volstaat hier: INT is geen bus
  met een klok zoals SDA en SCL (zie [6.4.3](../6_spi_en_i2c/6.4_i2c.md#643-i²c-op-de-esp32-en-de-firebeetle-2)), maar een melding.
- **Te delen**: meerdere IC's kunnen dezelfde INT-lijn gebruiken. Eén IC dat
  de lijn laag trekt, volstaat. De ISR weet dan wel niet welk IC de melding
  gaf: `loop()` leest ze allemaal uit.
- **Actief tot het IC uitgelezen wordt**: de lijn blijft laag tot het
  programma het IC, of een statusregister ervan, uitleest.

### Een port expander met drukknoppen

De **PCF8574** is een *port expander*: een IC met acht extra pinnen (P0–P7),
aangestuurd via I²C. Het adres ligt tussen 0x20 en 0x27, in te stellen met
de pinnen A0–A2 (0x38 tot 0x3F voor de PCF8574A). Na het opstarten staan alle
pinnen hoog, en werken ze als ingang: een drukknop tussen een pin en GND
volstaat.

De INT-pin van de PCF8574 is open drain en actief laag. Het IC trekt INT laag
bij elke verandering op een ingang, en laat INT los wanneer de master de
pinnen uitleest.

```cpp
#include <Wire.h>

const int EXPANDER_INT_PIN = 25;        // D2, INT of the PCF8574 (active low)
const uint8_t EXPANDER_ADDRESS = 0x20;  // A2, A1 and A0 to GND

volatile bool is_input_changed = false;  // flag: set by the ISR, cleared by loop()

void ARDUINO_ISR_ATTR mark_change_isr() {
  is_input_changed = true;
}

// Reads P0 to P7 in one byte (pressed = 0). Reading also releases INT.
uint8_t read_expander() {
  Wire.requestFrom(EXPANDER_ADDRESS, 1);
  return Wire.read();
}

void handle_inputs() {
  if (!is_input_changed) {
    return;
  }
  is_input_changed = false;
  uint8_t inputs = read_expander();
  Serial.printf("inputs: 0x%02X\n", inputs);
}

void setup() {
  Serial.begin(115200);
  Wire.begin();  // SDA = GPIO21, SCL = GPIO22
  pinMode(EXPANDER_INT_PIN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(EXPANDER_INT_PIN), mark_change_isr, FALLING);
  read_expander();  // releases INT, in case it is already active
}

void loop() {
  handle_inputs();
}
```

Wat opvalt:

- **De ISR leest de PCF8574 niet uit.** Uitlezen via I²C wacht op de
  transfer, en hoort dus niet in een ISR. De ISR zet enkel een vlag,
  `handle_inputs()` leest de pinnen uit in `loop()` (zie [7.6](./7.6_vlaggen.md)).
- **Wire in twee functies**: `Wire.requestFrom(EXPANDER_ADDRESS, 1)` vraagt
  één byte op (startconditie, adres met R-bit, data, NACK en stopconditie,
  zie [6.6](../6_spi_en_i2c/6.6_het_i2c_protocol.md)), `Wire.read()` geeft die byte terug. `Wire.begin()` gebruikt de
  standaardpinnen uit [6.4.3](../6_spi_en_i2c/6.4_i2c.md#643-i²c-op-de-esp32-en-de-firebeetle-2).
- **`read_expander()` in `setup()`.** Wordt er tijdens het opstarten al op een
  knop gedrukt, dan staat INT al laag wanneer de interrupt ingesteld wordt.
  Er volgt dan geen dalende flank meer, en de ISR wordt nooit opgeroepen. Eén
  keer uitlezen laat INT los.
- **`FALLING`, geen `ONLOW`.** INT blijft laag tot `loop()` de PCF8574
  uitleest. Met een niveau-interrupt zou de ISR in die tijd telkens opnieuw
  opgeroepen worden (zie [7.3.3](./7.3_gpio_interrupts_in_de_arduino_core.md#733-interrupt-modes)).
- **Voed de PCF8574 op 3,3 V.** Het IC werkt vanaf 2,5 V. Zo trekken de
  pull-ups van de module SDA en SCL niet naar 5 V (zie [6.4.3](../6_spi_en_i2c/6.4_i2c.md#643-i²c-op-de-esp32-en-de-firebeetle-2)).

> **Let op:** ook de drukknoppen op een PCF8574 denderen. Elke flank geeft
> een nieuwe melding op INT. `loop()` leest telkens de laatste toestand van
> de pinnen, maar om drukken te tellen is een debounce nodig, zoals in
> [7.7.1](./7.7_use_cases.md#771-een-drukknop-debouncen).

*Bron: [Texas Instruments, PCF8574 Remote 8-Bit I/O Expander for I²C Bus, datasheet](https://ti.com/document-viewer/PCF8574/datasheet/GUID-2A894D6C-2F33-4361-92DA-57EE6B4AAA90)*

## 7.8.3 Tellers: timers en de pulse counter

Een **teller** (*counter*) in hardware telt flanken, zonder dat de processor
eraan te pas komt. Wat de teller telt, bepaalt waarvoor hij dient:

- een **timer** telt de flanken van een klok, en meet zo de **tijd**;
- een **pulse counter** telt de flanken van een signaal van buitenaf,
  bijvoorbeeld de pulsen van een sensor.

Beide geven een interrupt wanneer de teller een ingestelde waarde bereikt.
In plaats van een interrupt bij elke flank, volgt er dus een interrupt na
**N flanken**. Of helemaal geen: het programma kan de teller ook gewoon
uitlezen wanneer het de waarde nodig heeft.

### Een hardware-timer

De ESP32 heeft vier timers van 64 bit. De ESP32-core heeft er drie functies
voor:

- `timerBegin(frequency)`: start een timer die telt aan de opgegeven
  frequentie, bijvoorbeeld 1 MHz: één tel per µs;
- `timerAttachInterrupt(timer, isr)`: de ISR bij een alarm;
- `timerAlarm(timer, alarm_value, autoreload, reload_count)`: een alarm
  wanneer de teller `alarm_value` bereikt. Met `autoreload` op `true` start
  de teller daarna opnieuw vanaf `reload_count`, meestal 0. Zo volgt er een
  interrupt met een vaste periode.

De driver van de timer roept de functie op vanuit zijn ISR: alle regels uit
[7.5](./7.5_de_ideale_isr.md) gelden. Een statusled die op een vast ritme knippert, los van wat
`loop()` doet:

```cpp
const int STATUS_LED_PIN = 2;                  // D9, built-in LED
const uint32_t TIMER_FREQUENCY_HZ = 1000000;   // one count per µs
const uint64_t BLINK_HALF_PERIOD_US = 500000;  // 1 Hz

hw_timer_t *blink_timer = NULL;

bool status_led_on = false;  // only used inside the ISR

void ARDUINO_ISR_ATTR toggle_status_led_isr() {
  status_led_on = !status_led_on;
  digitalWrite(STATUS_LED_PIN, status_led_on);
}

void setup() {
  pinMode(STATUS_LED_PIN, OUTPUT);
  blink_timer = timerBegin(TIMER_FREQUENCY_HZ);
  timerAttachInterrupt(blink_timer, toggle_status_led_isr);
  // true: after each alarm, the timer restarts from 0
  timerAlarm(blink_timer, BLINK_HALF_PERIOD_US, true, 0);
}

void loop() {
  // the LED keeps its rhythm, whatever loop() does
}
```

Voor enkel een knipperende led is PWM nog eenvoudiger (zie [4.6](../4_gpio/4.6_pwm.md)): dan
schakelt de hardware de pin zelf, zonder interrupt. Een timer-interrupt is
nodig wanneer er op vaste tijdstippen **code** moet lopen: een meting op een
vast tempo, een stappuls voor een stappenmotordriver, ...

### De pulse counter (PCNT)

De ESP32 heeft acht **pulse counters** (PCNT). Elke unit heeft:

- een teller van 16 bit, met teken: van -32768 tot 32767;
- twee **kanalen**. Elk kanaal heeft een *edge*-ingang, waarvan de flanken
  geteld worden, en een *level*-ingang, die de telrichting kan bepalen;
- een **glitch filter**, dat pulsen korter dan een ingestelde tijd negeert;
- **watch points**: waarden van de teller die een interrupt geven.

De Arduino core heeft geen functies voor de PCNT. Een sketch kan wel
rechtstreeks de driver van het ESP-IDF gebruiken: de ESP32-core is erop
gebouwd, en de headers van het ESP-IDF zijn ook in een sketch beschikbaar.

Niet elke ESP32-variant heeft een PCNT: de ESP32-S3 heeft er vier, de
ESP32-C3 geen enkele.

### Een waterteller

Een **flowsensor** zoals de YF-S201 geeft een puls per hoeveelheid water die
erdoor stroomt. Volgens het datasheet is de frequentie F = 7,5 × Q, met Q het
debiet in liter per minuut. Dat zijn 450 pulsen per liter.

Met een GPIO-interrupt volgt er een interrupt bij elke puls: 450 per liter.
Met een PCNT telt de hardware de pulsen, en volgt er **één interrupt per
liter**: de teller heeft een watch point op 450, en begint daarna automatisch
opnieuw vanaf 0.

```cpp
#include <driver/pulse_cnt.h>

const int FLOW_SENSOR_PIN = 25;       // D2, pulse output of the flow sensor
const int PULSES_PER_LITER = 450;     // YF-S201: F = 7.5 * Q (Q in l/min)
const uint32_t MAX_GLITCH_NS = 1000;  // shorter pulses are noise

pcnt_unit_handle_t flow_unit = NULL;

volatile bool is_liter_reached = false;  // flag: set by the ISR, cleared by loop()
volatile int liter_count = 0;            // written by the ISR only

bool ARDUINO_ISR_ATTR count_liter_isr(
  pcnt_unit_handle_t unit, const pcnt_watch_event_data_t *data, void *context
) {
  liter_count++;
  is_liter_reached = true;
  return false;  // no FreeRTOS task to wake up
}

void setup_flow_counter() {
  pcnt_unit_config_t unit_config = {
    .low_limit = -1,                 // must be below 0, never reached when counting up
    .high_limit = PULSES_PER_LITER,  // the counter restarts from 0 after each liter
  };
  ESP_ERROR_CHECK(pcnt_new_unit(&unit_config, &flow_unit));

  pcnt_glitch_filter_config_t filter_config = {
    .max_glitch_ns = MAX_GLITCH_NS,
  };
  ESP_ERROR_CHECK(pcnt_unit_set_glitch_filter(flow_unit, &filter_config));

  pcnt_chan_config_t channel_config = {
    .edge_gpio_num = FLOW_SENSOR_PIN,
    .level_gpio_num = -1,  // no level input
  };
  pcnt_channel_handle_t flow_channel = NULL;
  ESP_ERROR_CHECK(pcnt_new_channel(flow_unit, &channel_config, &flow_channel));

  ESP_ERROR_CHECK(pcnt_channel_set_edge_action(
    flow_channel,
    PCNT_CHANNEL_EDGE_ACTION_INCREASE,  // rising edge: +1
    PCNT_CHANNEL_EDGE_ACTION_HOLD       // falling edge: nothing
  ));

  ESP_ERROR_CHECK(pcnt_unit_add_watch_point(flow_unit, PULSES_PER_LITER));
  pcnt_event_callbacks_t callbacks = {
    .on_reach = count_liter_isr,
  };
  ESP_ERROR_CHECK(pcnt_unit_register_event_callbacks(flow_unit, &callbacks, NULL));

  ESP_ERROR_CHECK(pcnt_unit_enable(flow_unit));
  ESP_ERROR_CHECK(pcnt_unit_clear_count(flow_unit));
  ESP_ERROR_CHECK(pcnt_unit_start(flow_unit));
}

void handle_liter() {
  if (!is_liter_reached) {
    return;
  }
  is_liter_reached = false;
  int liters = liter_count;  // read the shared variable once
  Serial.printf("%d liter\n", liters);
}

void setup() {
  Serial.begin(115200);
  setup_flow_counter();
}

void loop() {
  handle_liter();
}
```

Wat opvalt:

- **De stijl van het ESP-IDF.** Configuratiestructs, handles en
  `ESP_ERROR_CHECK()`, zoals in [7.6.3](./7.6_vlaggen.md#763-onder-de-motorkap-het-esp-idf). De opbouw volgt de stappen uit de
  documentatie: een unit, een glitch filter, een kanaal met zijn acties, een
  watch point met een callback, en tot slot `enable`, `clear` en `start`.
- **De callback loopt in een ISR.** De driver roept `on_reach` op vanuit zijn
  ISR: daarom de suffix `_isr` en `ARDUINO_ISR_ATTR`. De returnwaarde zegt of
  er een FreeRTOS-taak gewekt werd, hier niet.
- **Het patroon van [7.6](./7.6_vlaggen.md)**: de ISR telt de liters en zet een vlag,
  `handle_liter()` print in `loop()`. Ook de vuistregels uit [7.4.3](./7.4_gedeelde_variabelen_en_volatile.md#vuistregels) gelden:
  enkel de ISR schrijft `liter_count`, en `loop()` leest de variabele één
  keer.
- **Wat er tussen twee liters gebeurt**, staat in de teller zelf.
  `pcnt_unit_get_count()` geeft het aantal pulsen sinds de laatste volle
  liter, en mag op elk moment opgeroepen worden.
- **Het spanningsniveau.** Een YF-S201 op 5 V geeft pulsen van 5 V: een
  spanningsdeler is nodig (zie [4.4.3](../4_gpio/4.4_digitale_input.md#443-spanningsniveaus-combineren)).

Bij een debiet van hoogstens 30 liter per minuut geeft de YF-S201 225 pulsen
per seconde. Dat kan een GPIO-interrupt ook nog volgen. Het verschil wordt
groot bij hogere frequenties, zoals de encoder op de as van een motor: daar
lopen de pulsen op tot duizenden per seconde.

> **Let op:** het glitch filter werkt met de APB-klok van 80 MHz, en kan
> hoogstens 1023 klokperiodes negeren: ongeveer 12,8 µs. Dat volstaat tegen
> korte storingspieken, maar niet tegen contactdender, die tot enkele
> milliseconden duurt (zie [4.4.6](../4_gpio/4.4_digitale_input.md#446-drukknoppen-zijn-niet-digitaal)).

### Een rotary encoder in hardware

Met de level-ingang kan de PCNT ook de rotary encoder uit [7.7.2](./7.7_use_cases.md#772-een-rotary-encoder-met-interrupts) uitlezen,
volledig in hardware. Kanaal A gaat naar de edge-ingang, kanaal B naar de
level-ingang:

```cpp
pcnt_chan_config_t channel_config = {
  .edge_gpio_num = ENCODER_A_PIN,
  .level_gpio_num = ENCODER_B_PIN,
};

ESP_ERROR_CHECK(pcnt_channel_set_edge_action(
  encoder_channel,
  PCNT_CHANNEL_EDGE_ACTION_HOLD,     // rising edge of A: nothing
  PCNT_CHANNEL_EDGE_ACTION_INCREASE  // falling edge of A: +1
));
ESP_ERROR_CHECK(pcnt_channel_set_level_action(
  encoder_channel,
  PCNT_CHANNEL_LEVEL_ACTION_KEEP,    // B HIGH: keep counting up
  PCNT_CHANNEL_LEVEL_ACTION_INVERSE  // B LOW: count down instead
));
```

Dat is precies de logica van `update_position_isr()`: bij een dalende flank
op A, kanaal B uitlezen en op basis daarvan +1 of -1. Alleen gebeurt het nu
zonder ISR, en mist de teller geen enkele flank. `loop()` leest de positie
met `pcnt_unit_get_count()`. Ook hier blijft een RC-filter per kanaal nodig
tegen contactdender.

## 7.8.4 Historiek: EXT_INT en PIN_CHANGE op de AVR

De ATmega328P van de Arduino Nano (zie [1.1](../1_introductie/1.1_wat_is_arduino.md)) kent twee soorten interrupts
op een pin. Het datasheet beschrijft ze samen, onder *External Interrupts*:

- **EXT_INT**: de *external interrupts* `INT0` en `INT1`;
- **PIN_CHANGE**: de *pin change interrupts* `PCINT0` tot `PCINT23`.

Ze verklaren waarom `attachInterrupt()` op de Nano maar op twee pinnen werkt
(zie [7.3.2](./7.3_gpio_interrupts_in_de_arduino_core.md#732-welke-pinnen-kunnen-een-interrupt-geven)). De voorbeelden hieronder zijn voor de Nano, en spreken de
registers rechtstreeks aan, zoals het voorbeeld zonder Arduino core in
[1.1.3](../1_introductie/1.1_wat_is_arduino.md#113-de-arduino-core-software).

### EXT_INT: INT0 en INT1

- **Twee pinnen**: `INT0` op D2 (PD2) en `INT1` op D3 (PD3).
- **Een eigen ISR per pin**: `INT0_vect` en `INT1_vect`. De ISR weet dus
  meteen welke pin de interrupt gaf.
- **Vier modes**, per pin in te stellen met twee bits in het register
  `EICRA`:

  | `ISC01` | `ISC00` | Interrupt bij `INT0`  | Arduino   |
  | ------- | ------- | --------------------- | --------- |
  | 0       | 0       | laag niveau           | `LOW`     |
  | 0       | 1       | elke verandering      | `CHANGE`  |
  | 1       | 0       | dalende flank         | `FALLING` |
  | 1       | 1       | stijgende flank       | `RISING`  |

- **Aan- en uitzetten** met het bit `INT0` of `INT1` in het register `EIMSK`.

De constanten van de AVR-core hebben precies de waarde van die twee bits:
`LOW` is 0, `CHANGE` 1, `FALLING` 2 en `RISING` 3. `attachInterrupt()` schuift
de mode gewoon in `EICRA`, net zoals de ESP32-core de laagste drie bits van
de mode doorgeeft aan het ESP-IDF (zie [7.6.3](./7.6_vlaggen.md#763-onder-de-motorkap-het-esp-idf)).

Het voorbeeld uit [7.3.1](./7.3_gpio_interrupts_in_de_arduino_core.md#731-attachinterrupt), zonder `attachInterrupt()`:

```cpp
const int BUTTON_PIN = 2;  // D2 = PD2 = INT0
const int LED_PIN = 13;    // built-in LED of the Nano

bool led_on = false;  // only used inside the ISR

ISR(INT0_vect) {
  led_on = !led_on;
  digitalWrite(LED_PIN, led_on);
}

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  EICRA = (EICRA & ~(1 << ISC00)) | (1 << ISC01);  // ISC01 ISC00 = 1 0: falling edge
  EIMSK |= (1 << INT0);                            // enable INT0
}

void loop() {
  // nothing to do here: the ISR toggles the LED
}
```

Wat opvalt:

- **`ISR(INT0_vect)`** is een macro van de AVR-compiler (avr-libc). Ze koppelt
  de functie rechtstreeks aan de interruptvector: de naam van de ISR ligt
  dus vast.
- **`(1 << ISC01)`** is een byte waarin enkel bit `ISC01` op 1 staat. `|=`
  zet dat bit in het register op 1, `& ~` zet het op 0. De andere bits blijven
  ongewijzigd.
- **Niet samen met `attachInterrupt()`.** De AVR-core definieert zelf al een
  ISR voor `INT0_vect`. Worden beide gebruikt, dan meldt de linker een
  dubbele definitie (`multiple definition of __vector_1`).

### PIN_CHANGE: PCINT0 tot PCINT23

- **Bijna elke pin**: D0–D13 en A0–A5. A6 en A7 van de Nano zijn enkel
  analoog, en hebben geen pin change interrupt.
- **Eén ISR per poort**: alle pinnen van een poort delen één ISR.

  | ISR           | Pinnen             | Poort | Aanzetten: `PCICR` | Pinnen kiezen |
  | ------------- | ------------------ | ----- | ------------------ | ------------- |
  | `PCINT0_vect` | D8–D13             | B     | `PCIE0`            | `PCMSK0`      |
  | `PCINT1_vect` | A0–A5              | C     | `PCIE1`            | `PCMSK1`      |
  | `PCINT2_vect` | D0–D7              | D     | `PCIE2`            | `PCMSK2`      |

- **Enkel "verandering"**: geen keuze tussen stijgend en dalend. De ISR moet
  zelf uitzoeken **welke** pin veranderde, en in **welke richting**.

Daarvoor leest de ISR het register `PINB`: de niveaus van alle pinnen van
poort B in één byte. De vergelijking met de vorige waarde toont welke pinnen
veranderd zijn. Twee drukknoppen op D8 en D9:

```cpp
const int BUTTON_1_PIN = 8;  // D8 = PB0 = PCINT0
const int BUTTON_2_PIN = 9;  // D9 = PB1 = PCINT1

volatile bool is_button_1_pressed = false;  // flag: set by the ISR, cleared by loop()
volatile bool is_button_2_pressed = false;  // flag: set by the ISR, cleared by loop()

uint8_t last_port_b = 0xFF;  // levels of port B at the previous interrupt

// called on any change on D8 to D13
ISR(PCINT0_vect) {
  uint8_t port_b = PINB;                    // the levels of all pins of port B at once
  uint8_t falling = last_port_b & ~port_b;  // 1 = went from HIGH to LOW
  last_port_b = port_b;

  if (falling & (1 << PB0)) {
    is_button_1_pressed = true;
  }
  if (falling & (1 << PB1)) {
    is_button_2_pressed = true;
  }
}

void handle_buttons() {
  if (is_button_1_pressed) {
    is_button_1_pressed = false;
    Serial.println("button 1 pressed");
  }
  if (is_button_2_pressed) {
    is_button_2_pressed = false;
    Serial.println("button 2 pressed");
  }
}

void setup() {
  Serial.begin(9600);
  pinMode(BUTTON_1_PIN, INPUT_PULLUP);
  pinMode(BUTTON_2_PIN, INPUT_PULLUP);
  last_port_b = PINB;                       // before the interrupt is enabled
  PCMSK0 |= (1 << PCINT0) | (1 << PCINT1);  // D8 and D9 take part
  PCICR |= (1 << PCIE0);                    // enable PCINT0_vect (port B)
}

void loop() {
  handle_buttons();
}
```

Wat opvalt:

- **`last_port_b & ~port_b`** geeft een 1 voor elke pin die vroeger HIGH was
  en nu LOW is: een dalende flank, bij een pull-up een druk op de knop.
- **De ISR doet meer werk** dan bij `INT0`: registers lezen en vergelijken.
  Dat is de prijs voor één ISR voor acht pinnen.
- **Geen ondersteuning in de AVR-core.** `attachInterrupt()` kent geen pin
  change interrupts. Bibliotheken zoals *PinChangeInterrupt* voorzien dat
  wel. Ook *SoftwareSerial* gebruikt de `PCINT`-vectoren: die bibliotheek kan
  dus niet samen met een eigen `ISR(PCINT0_vect)`.

### Slaapmodi

Het datasheet maakt nog een verschil. Een **flank** op `INT0` of `INT1` wordt
gedetecteerd met de I/O-klok. Een **laag niveau** op `INT0` of `INT1`, en elke
**pin change**, wordt gedetecteerd zonder klok (*asynchroon*). Enkel die
laatste kunnen de ATmega328P wekken uit een andere slaapmodus dan *Idle*,
zoals *power-down*: de I/O-klok staat dan stil. Daar is de mode `LOW` wel
zinvol, ook al wordt een niveau-interrupt voor een knop in het algemeen
afgeraden (zie [7.3.3](./7.3_gpio_interrupts_in_de_arduino_core.md#733-interrupt-modes)).

### Vergelijking met de ESP32

|                          | EXT_INT (`INT0`, `INT1`)        | PIN_CHANGE (`PCINT`)       | ESP32                           |
| ------------------------ | ------------------------------- | -------------------------- | ------------------------------- |
| Pinnen                   | D2 en D3                        | bijna alle                 | elke GPIO                       |
| ISR in de hardware       | één per pin                     | één per poort (acht pinnen) | één voor alle GPIO              |
| Modes                    | `LOW`, `CHANGE`, `FALLING`, `RISING` | enkel verandering     | acht (zie [7.3.3](./7.3_gpio_interrupts_in_de_arduino_core.md#733-interrupt-modes))    |
| Welke pin?               | ligt vast                       | zoekt de ISR zelf uit      | zoekt de ISR service uit        |
| `attachInterrupt()`      | ja                              | nee                        | ja                              |

Op de ESP32 is er voor alle GPIO samen **één interrupt**. De GPIO ISR service
uit [7.6.3](./7.6_vlaggen.md#763-onder-de-motorkap-het-esp-idf) leest een statusregister, en roept voor elke pin met een interrupt
de juiste handler op. Dat is in software wat de ISR met `PINB` hierboven
doet. Het verschil: bij de ESP32 stelt de hardware per pin de mode in. De ISR
service moet dus enkel uitzoeken **welke** pin de interrupt gaf, niet in welke
richting. En `attachInterrupt()` verbergt de rest.
