# 7.7 Use cases

De use cases in deze sectie brengen samen wat in dit hoofdstuk aan bod kwam:

- een ISR die enkel het tijdsgebonden deel doet (zie [7.5](./7.5_de_ideale_isr.md));
- een vlag of een teller om het werk door te geven aan `loop()` (zie [7.6](./7.6_vlaggen.md));
- de vuistregels voor gedeelde variabelen (zie [7.4.3](./7.4_gedeelde_variabelen_en_volatile.md#vuistregels)).

## 7.7.1 Een drukknop debouncen

Een interrupt reageert op elke flank, ook op de flanken van contactdender
(zie [7.3.1](./7.3_gpio_interrupts_in_de_arduino_core.md#731-attachinterrupt)). De netste oplossing zit in hardware: met een RC-filter en
een Schmitt-trigger (zie [4.4.6](../4_gpio/4.4_digitale_input.md#446-drukknoppen-zijn-niet-digitaal)) komt er per druk precies één flank aan
op de pin.

In software kan het ook, door het werk te verdelen:

- de **ISR** noteert bij elke flank het tijdstip, en zet een vlag;
- **`loop()`** wacht tot er een tijd lang geen flank meer geweest is. Pas dan
  is de knop stabiel, en wordt de pin uitgelezen.

Dat is dezelfde aanpak als de debounce in [4.4.6](../4_gpio/4.4_digitale_input.md#446-drukknoppen-zijn-niet-digitaal), met één verschil: het
detecteren van een verandering gebeurt niet meer door `loop()`, maar door de
interrupt.

```cpp
const int BUTTON_PIN = 25;                    // D2
const int LED_PIN = 2;                        // D9, built-in LED
const unsigned long DEBOUNCE_DELAY_MS = 50;

volatile bool is_edge_detected = false;   // flag: set by the ISR, cleared by loop()
volatile unsigned long last_edge_ms = 0;  // written by the ISR only

int button_state = HIGH;  // stable state (pull-up: released = HIGH)
int led_state = LOW;

void ARDUINO_ISR_ATTR record_edge_isr() {
  last_edge_ms = millis();  // every edge restarts the debounce time
  is_edge_detected = true;
}

void handle_button() {
  if (!is_edge_detected) {
    return;  // nothing happened
  }
  if (millis() - last_edge_ms < DEBOUNCE_DELAY_MS) {
    return;  // still bouncing
  }
  is_edge_detected = false;
  int reading = digitalRead(BUTTON_PIN);
  if (reading != button_state) {
    button_state = reading;
    if (button_state == LOW) {  // pressed
      led_state = !led_state;
      digitalWrite(LED_PIN, led_state);
    }
  }
}

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(BUTTON_PIN), record_edge_isr, CHANGE);
}

void loop() {
  handle_button();
}
```

Wat opvalt:

- **`CHANGE`**: zowel het indrukken als het loslaten geeft flanken, en beide
  moeten de debounce-tijd herstarten.
- **`millis()` in de ISR** mag op de ESP32: de functie leest enkel een timer
  uit (zie [7.5.2](./7.5_de_ideale_isr.md#752-wat-niet-in-een-isr-thuishoort)).
- **`loop()` beslist**, niet de ISR. Of de knop ingedrukt of losgelaten is,
  wordt pas bepaald wanneer het contact stabiel is. Een flank van het
  loslaten wordt zo nooit als een nieuwe druk geteld.

Voor een knop die door een mens ingedrukt wordt, is polling zoals in
[4.4.6](../4_gpio/4.4_digitale_input.md#446-drukknoppen-zijn-niet-digitaal) vaak even goed: een druk duurt al snel 100 ms, ruim langer dan één
doorloop van `loop()`. Deze use case toont vooral hoe het werk tussen de ISR
en `loop()` verdeeld wordt. Bij een signaal dat echt snel verandert, zoals
dat van een encoder, maakt een interrupt wel het verschil.

## 7.7.2 Een rotary encoder met interrupts

De rotary encoder uit [4.4.7](../4_gpio/4.4_digitale_input.md#447-use-cases) miste stappen wanneer er snel gedraaid werd: de
sketch las kanaal A enkel uit wanneer `loop()` daar aan toe kwam. Met een
interrupt op kanaal A wordt elke dalende flank opgemerkt, ook terwijl
`loop()` met iets anders bezig is.

```cpp
const int ENCODER_A_PIN = 25;  // D2
const int ENCODER_B_PIN = 26;  // D3

volatile int position = 0;  // written by the ISR only

int last_position = 0;  // the last position printed by loop()

void ARDUINO_ISR_ATTR update_position_isr() {
  if (digitalRead(ENCODER_B_PIN) == HIGH) {
    position++;  // clockwise
  } else {
    position--;  // counterclockwise
  }
}

void print_position() {
  int current_position = position;  // read the shared variable once
  if (current_position != last_position) {
    last_position = current_position;
    Serial.println(current_position);
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(ENCODER_A_PIN, INPUT_PULLUP);
  pinMode(ENCODER_B_PIN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(ENCODER_A_PIN), update_position_isr, FALLING);
}

void loop() {
  print_position();
}
```

Wat opvalt:

- **De richting wordt in de ISR bepaald.** Kanaal B moet uitgelezen worden op
  het moment van de flank op A: dat is het tijdsgebonden deel, en hoort dus in
  de ISR. `digitalRead()` mag in een ISR (zie [7.5.2](./7.5_de_ideale_isr.md#752-wat-niet-in-een-isr-thuishoort)).
- **Beide vuistregels uit [7.4.3](./7.4_gedeelde_variabelen_en_volatile.md#vuistregels)**: enkel de ISR past `position` aan, en
  `print_position()` leest de variabele één keer, in `current_position`. Wat
  al geprint is, houdt `loop()` bij in een eigen variabele, `last_position`.
- **Printen kan achterop raken, tellen niet.** Wordt er sneller gedraaid dan
  `Serial` kan volgen, dan slaat de uitvoer tussenliggende waarden over. De
  positie zelf mist geen stap, omdat de ISR elke flank telt.

> **Let op:** contactdender geeft bij een encoder extra flanken, en dus extra
> of verkeerde stappen. Een RC-filter per kanaal is bij een encoder met
> interrupts sterk aangeraden (zie [4.4.7](../4_gpio/4.4_digitale_input.md#447-use-cases)).

## 7.7.3 Een noodstop

In de vorige use cases deed de ISR enkel het tijdsgebonden deel, en schoof ze
de rest door naar `loop()`. Soms is de **actie zelf** tijdsgebonden. Een motor
die een slede tegen een eindpunt aan drijft, moet stoppen op het moment dat
de stopknop of de eindeloopschakelaar geraakt wordt, en niet pas wanneer
`loop()` de knop uitleest. Duurt één doorloop van `loop()` 20 ms (zie
[7.1.3](./7.1_de_superloop.md#713-de-reactietijd-van-een-superloop)), dan draait de motor nog tot 20 ms door.

In dat geval schakelt de ISR de motor **zelf** uit. Dat is één
`digitalWrite()`: kort, en toegelaten in een ISR (zie [7.5.2](./7.5_de_ideale_isr.md#752-wat-niet-in-een-isr-thuishoort)). De rest
gebeurt zoals altijd in `loop()`, via een vlag: een melding geven, de
alarmled aansturen en de motor opnieuw starten.

### De schakeling

- De **motor** hangt aan een N-channel MOSFET op D10, zoals in [4.3.5](../4_gpio/4.3_digitale_output.md#een-mosfet-aansturen) en
  [A2.4](../appendix_2_mosfet_schakelen/appendix_2_mosfet_schakelen.md#a24-low-side-switch-met-de-2n7000). De weerstand tussen gate en GND houdt de motor uit tijdens het
  opstarten, nog voor de sketch loopt.
- De **stopknop** zit tussen D2 en GND, en heeft een **normaal gesloten**
  contact (*normally closed*, NC):
  - niet ingedrukt: het contact is gesloten en trekt de pin LOW;
  - ingedrukt: het contact opent, en de interne pull-up trekt de pin HIGH.
    Dat is een stijgende flank, dus de mode is `RISING`.
- De **startknop** is een gewone drukknop (normaal open) tussen D3 en GND.

Waarom een normaal gesloten contact? Breekt er een draad of valt er een
connector los, dan wordt de pin ook HIGH, en stopt de motor. Met een normaal
open contact zou een losse draad de stopknop ongemerkt buiten werking zetten.
Een fout in de bedrading leidt zo naar de veilige toestand (*fail-safe*).
Noodstopknoppen hebben daarom normaal gesloten contacten.

### De code

```cpp
const int STOP_PIN = 25;      // D2, normally closed stop button to GND
const int START_PIN = 26;     // D3, normally open start button to GND
const int MOTOR_PIN = 17;     // D10, gate of the MOSFET
const int ALARM_LED_PIN = 2;  // D9, built-in LED

volatile bool is_stop_triggered = false;  // flag: set by the ISR, cleared by loop()

void ARDUINO_ISR_ATTR stop_motor_isr() {
  digitalWrite(MOTOR_PIN, LOW);  // time-critical: switch the motor off immediately
  is_stop_triggered = true;
}

// True while the motor must stay off: the stop button is pressed,
// a wire is broken, or loop() has not yet handled a stop from the ISR.
bool is_stop_active() {
  return digitalRead(STOP_PIN) == HIGH || is_stop_triggered;
}

void handle_stop() {
  if (!is_stop_triggered) {
    return;
  }
  is_stop_triggered = false;
  digitalWrite(ALARM_LED_PIN, HIGH);
  Serial.println("stop: motor switched off");
}

void start_motor() {
  if (is_stop_active()) {
    return;
  }
  digitalWrite(ALARM_LED_PIN, LOW);
  digitalWrite(MOTOR_PIN, HIGH);
  if (is_stop_active()) {
    digitalWrite(MOTOR_PIN, LOW);  // stopped between the check and the start
  }
}

void handle_start_button() {
  if (digitalRead(START_PIN) == LOW) {  // polling: a person presses this button
    start_motor();
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(MOTOR_PIN, OUTPUT);
  digitalWrite(MOTOR_PIN, LOW);
  pinMode(ALARM_LED_PIN, OUTPUT);
  pinMode(STOP_PIN, INPUT_PULLUP);
  pinMode(START_PIN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(STOP_PIN), stop_motor_isr, RISING);
}

void loop() {
  handle_stop();
  handle_start_button();
  // ... the other tasks, such as updating a display
}
```

Wat opvalt:

- **De ISR schakelt de motor zelf uit**, en zet daarna een vlag. Het melden en
  het aansturen van de alarmled zijn niet dringend, en gebeuren in `loop()`.
- **Dender maakt hier niets uit.** Het contact dendert bij het openen, dus de
  ISR wordt mogelijk een paar keer kort na elkaar uitgevoerd. Elke keer doet
  ze hetzelfde: de motor uitschakelen en de vlag zetten. Een ISR die bij een
  herhaling niets anders doet dan de eerste keer, heeft geen debounce nodig.
- **De startknop wordt gepold** (zie [7.2.4](./7.2_wat_is_een_interrupt.md#724-polling-tegenover-interrupts)): wie op start drukt, merkt
  geen verschil van enkele milliseconden.
- **`is_stop_active()` kijkt naar het niveau van de pin**, en niet enkel naar de
  vlag. Een noodstopknop blijft ingedrukt tot hij teruggedraaid wordt. Zolang
  dat niet gebeurd is, start de motor niet, ook al is de vlag al verwerkt.
- **`start_motor()` controleert twee keer**: vóór en na het aanzetten van de
  motor. Zonder de tweede controle kan het volgende gebeuren:
  1. `start_motor()` controleert de stopknop: niet ingedrukt;
  2. de stopknop wordt ingedrukt, en de ISR schakelt de motor uit;
  3. `start_motor()` zet de motor terug aan.

  Dat is hetzelfde probleem als in [7.4.3](./7.4_gedeelde_variabelen_en_volatile.md#743-volatile-is-niet-genoeg): een controle en de actie die
  erop volgt, gebeuren niet in één keer. De tweede controle merkt een
  interrupt die er net tussen viel.

> **Let op:** dit is een stop **in software**, geschikt voor een
> eindeloopschakelaar of een stopknop in een labo-opstelling. Bij een echte
> machine mag een noodstop niet afhangen van een programma: een fout in de
> code, een vastgelopen microcontroller of een doorgeslagen MOSFET houdt de
> motor dan niet tegen. De normen voor machineveiligheid, zoals EN ISO 13850 en
> EN 60204-1, vragen daarom dat de noodstop de energie onderbreekt via
> hardware, bijvoorbeeld een veiligheidsrelais. De microcontroller meldt dan
> enkel dat de noodstop ingedrukt werd.
