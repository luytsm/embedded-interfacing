# 7.6 Vlaggen

Een korte ISR (zie [7.5.3](./7.5_de_ideale_isr.md#753-zo-kort-mogelijk)) betekent dat het werk verdeeld wordt: de ISR
doet enkel het tijdsgebonden deel, `loop()` doet de rest. De ISR laat aan
`loop()` weten dat er iets gebeurd is met een **vlag** (*flag*): een
variabele die op `true` gezet wordt, zoals het vlagje op een Amerikaanse
brievenbus dat omhoog gaat wanneer er post is.

## 7.6.1 Het principe

- Er is een variabele die in de **scope** van zowel `loop()` als de ISR zit:
  - een **globale variabele**;
  - of data die via een pointer aan de ISR meegegeven wordt, met
    `attachInterruptArg()` (zie [7.6.2](#762-attachinterruptarg)).
- De **ISR zet de vlag**, en doet verder zo weinig mogelijk.
- **`loop()` verwerkt de vlag** daarna: ze controleert de vlag, zet ze terug
  op `false`, en voert het eigenlijke werk uit.

Het deurcontact uit [7.5.3](./7.5_de_ideale_isr.md#753-zo-kort-mogelijk), volledig uitgewerkt. Een *reed switch* zit tussen
D2 en GND. Zolang de deur dicht is, houdt de magneet in de deur het contact
gesloten, en is de pin LOW. Gaat de deur open, dan opent het contact en
trekt de interne pull-up de pin HIGH: een stijgende flank.

```cpp
const int DOOR_PIN = 25;                      // D2, reed switch to GND
const int ALARM_LED_PIN = 17;                 // D10
const unsigned long ALARM_DURATION_MS = 2000;

volatile bool is_door_opened = false;  // flag: set by the ISR, cleared by loop()
volatile int open_count = 0;           // written by the ISR only

bool is_alarm_on = false;
unsigned long alarm_start_ms = 0;

void ARDUINO_ISR_ATTR mark_door_isr() {
  open_count++;
  is_door_opened = true;
}

void handle_door() {
  if (!is_door_opened) {
    return;
  }
  is_door_opened = false;  // clear first: a new interrupt sets the flag again
  Serial.printf("door opened (%d times)\n", open_count);
  digitalWrite(ALARM_LED_PIN, HIGH);
  is_alarm_on = true;
  alarm_start_ms = millis();
}

void update_alarm() {
  if (is_alarm_on && millis() - alarm_start_ms >= ALARM_DURATION_MS) {
    digitalWrite(ALARM_LED_PIN, LOW);
    is_alarm_on = false;
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(ALARM_LED_PIN, OUTPUT);
  pinMode(DOOR_PIN, INPUT_PULLUP);
  attachInterrupt(digitalPinToInterrupt(DOOR_PIN), mark_door_isr, RISING);
}

void loop() {
  handle_door();
  update_alarm();
}
```

Wat opvalt:

- **De ISR telt twee regels**: een teller verhogen en een vlag zetten. Het
  printen en het aansturen van de alarmled gebeurt in `loop()`, zonder
  `delay()` (zie [A3.3](../appendix_3_static/appendix_3_static.md#a33-use-case-een-non-blocking-timer) voor het werken met `millis()`).
- **`loop()` leest als een inhoudstafel** (zie [A1.3.2](../appendix_1_codestandaarden/appendix_1_codestandaarden.md#a132-een-korte-loop)).
- **`handle_door()` zet de vlag eerst terug**, en doet pas daarna het werk.
  Gaat de deur opnieuw open terwijl `handle_door()` nog bezig is, dan zet de
  ISR de vlag opnieuw, en verwerkt de volgende doorloop van `loop()` die
  melding. Wordt de vlag pas op het einde teruggezet, dan gaat zo'n melding
  verloren.
- **`open_count` wordt enkel door de ISR aangepast**, volgens de eerste
  vuistregel uit [7.4.3](./7.4_gedeelde_variabelen_en_volatile.md#vuistregels). De vlag wordt wel door beide kanten geschreven. Op
  de ESP32 gebeurt het schrijven van een `bool` in één instructie, dus in het
  slechtste geval smelten twee meldingen die vlak na elkaar komen samen tot
  één bericht. De teller blijft wel correct.

> **Let op:** ook een reed switch dendert (zie [4.4.6](../4_gpio/4.4_digitale_input.md#446-drukknoppen-zijn-niet-digitaal)). Bij één keer openen
> kan `open_count` dus meerdere stappen verspringen. Voor een alarm maakt dat
> weinig uit, voor een teller wel (zie [7.7.1](./7.7_use_cases.md#771-een-drukknop-debouncen)).

## 7.6.2 attachInterruptArg()

Met `attachInterrupt()` kent de ISR geen parameters, en moet ze dus
rechtstreeks naar globale variabelen verwijzen. Voor twee knoppen zijn er
dan twee ISR's nodig, die bijna hetzelfde doen. `attachInterruptArg()` geeft
de ISR een **argument** mee:

```cpp
attachInterruptArg(uint8_t pin, voidFuncPtrArg handler, void *arg, int mode);
```

- **`pin`**: de GPIO, zoals bij `attachInterrupt()`.
- **`handler`**: de ISR. `voidFuncPtrArg` is een pointer naar een functie met
  één parameter van het type `void *`.
- **`arg`**: een pointer naar de data voor de ISR. Bij elke interrupt krijgt de
  ISR deze pointer mee.
- **`mode`**: de interrupt mode (zie [7.3.3](./7.3_gpio_interrupts_in_de_arduino_core.md#733-interrupt-modes)).

Een **`void *`** is een pointer naar "eender wat": de core weet niet welk type
data de sketch meegeeft, en hoeft dat ook niet te weten. De ISR zet de pointer
terug om naar het juiste type, met een **cast**.

Een voorbeeld met twee knoppen en één ISR. De gegevens van elke knop zitten
in een `struct` (zie [A3.3.6](../appendix_3_static/appendix_3_static.md#a336-een-herbruikbare-timer)):

```cpp
const int BUTTON_1_PIN = 25;  // D2
const int BUTTON_2_PIN = 26;  // D3

struct button_t {
  const int pin;
  volatile int press_count;  // written by the ISR only
  volatile bool is_pressed;  // flag: set by the ISR, cleared by loop()
};

button_t button_1 = { BUTTON_1_PIN, 0, false };
button_t button_2 = { BUTTON_2_PIN, 0, false };

void ARDUINO_ISR_ATTR count_press_isr(void *arg) {
  button_t *button = (button_t *)arg;  // arg points to button_1 or button_2
  button->press_count++;
  button->is_pressed = true;
}

void handle_button(button_t *button) {
  if (button->is_pressed) {
    button->is_pressed = false;
    Serial.printf("button on GPIO%d pressed %d times\n", button->pin, button->press_count);
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(button_1.pin, INPUT_PULLUP);
  pinMode(button_2.pin, INPUT_PULLUP);
  attachInterruptArg(digitalPinToInterrupt(button_1.pin), count_press_isr, &button_1, FALLING);
  attachInterruptArg(digitalPinToInterrupt(button_2.pin), count_press_isr, &button_2, FALLING);
}

void loop() {
  handle_button(&button_1);
  handle_button(&button_2);
}
```

Wat opvalt:

- **Eén ISR voor beide knoppen.** Bij een druk op D2 krijgt
  `count_press_isr()` het adres van `button_1` mee, bij een druk op D3 dat van
  `button_2`.
- **`(button_t *)arg`** zet de `void *` terug om naar een pointer naar een
  `button_t`. Het voorbeeld van Espressif schrijft hetzelfde in C++-stijl:
  `static_cast<button_t *>(arg)`. Beide doen hier hetzelfde.
- **`button->press_count`** is het veld `press_count` van de `struct` waar
  `button` naar wijst (zie [A3.3.6](../appendix_3_static/appendix_3_static.md#a336-een-herbruikbare-timer)).
- **Enkel de velden die de ISR aanpast, zijn `volatile`.** De pin verandert
  nooit, en is `const`.
- `button_1` en `button_2` zijn nog steeds globale variabelen, maar de ISR
  verwijst er niet meer rechtstreeks naar. Een derde knop vraagt dus enkel
  een extra `button_t` en een extra `attachInterruptArg()`, geen nieuwe ISR.

*Bron: gebaseerd op het voorbeeld `GPIOInterrupt` uit de [ESP32 Arduino core](https://github.com/espressif/arduino-esp32/tree/master/libraries/ESP32/examples/GPIO/GPIOInterrupt)*

## 7.6.3 Onder de motorkap: het ESP-IDF

### Wat attachInterrupt() doet

Net zoals `digitalWrite()` (zie [2.3](../2_arduino/2.3_de_arduino_core.md)) is `attachInterrupt()` in de ESP32 Arduino
core een laagje rond het ESP-IDF. De functies staan in
`cores/esp32/esp32-hal-gpio.c` (versie 3.3.12). Bij de eerste oproep wordt de
**GPIO ISR service** van het ESP-IDF geïnstalleerd, één keer voor alle
GPIO-interrupts:

```c
  if (!interrupt_initialized) {
    esp_err_t err = gpio_install_isr_service((int)ARDUINO_ISR_FLAG);
    interrupt_initialized = (err == ESP_OK) || (err == ESP_ERR_INVALID_STATE);
  }
```

`ARDUINO_ISR_FLAG` is de vlag uit [7.3.4](./7.3_gpio_interrupts_in_de_arduino_core.md#arduino_isr_attr-en-iram_attr): standaard `0`. Verderop in dezelfde functie:

```c
  gpio_set_intr_type((gpio_num_t)pin, (gpio_int_type_t)(intr_type & 0x7));
  if (intr_type & 0x8) {
    gpio_wakeup_enable((gpio_num_t)pin, (gpio_int_type_t)(intr_type & 0x7));
  }
  gpio_isr_handler_add((gpio_num_t)pin, __onPinInterrupt, &__pinInterruptHandlers[pin]);
```

- **`intr_type & 0x7`** houdt de laagste drie bits van de mode over. De
  Arduino-modes zijn zo genummerd dat die drie bits overeenkomen met het type
  `gpio_int_type_t` van het ESP-IDF (zie de tabel hieronder).
- **`intr_type & 0x8`** test bit 3: dat is de *wake enable*. `ONLOW_WE` is
  `0x0C`, of `0x08` + `ONLOW` (`0x04`). Is dat bit gezet, dan roept de core
  ook `gpio_wakeup_enable()` op.
- **`gpio_isr_handler_add()`** koppelt niet de ISR uit de sketch aan de pin,
  maar een functie van de core zelf, `__onPinInterrupt()`. Die roept op haar
  beurt de ISR uit de sketch op, met of zonder argument:

```c
static void ARDUINO_ISR_ATTR __onPinInterrupt(void *arg) {
  InterruptHandle_t *isr = (InterruptHandle_t *)arg;
  if (isr->fn) {
    if (isr->arg) {
      ((voidFuncPtrArg)isr->fn)(isr->arg);
    } else {
      isr->fn();
    }
  }
}
```

Daarom heeft een ISR voor `attachInterrupt()` geen parameters, terwijl een
handler in het ESP-IDF altijd een `void *arg` krijgt.

| Arduino     | Waarde | ESP-IDF (`gpio_int_type_t`)                   |
| ----------- | ------ | --------------------------------------------- |
| `DISABLED`  | `0x00` | `GPIO_INTR_DISABLE`                           |
| `RISING`    | `0x01` | `GPIO_INTR_POSEDGE`                           |
| `FALLING`   | `0x02` | `GPIO_INTR_NEGEDGE`                           |
| `CHANGE`    | `0x03` | `GPIO_INTR_ANYEDGE`                           |
| `ONLOW`     | `0x04` | `GPIO_INTR_LOW_LEVEL`                         |
| `ONHIGH`    | `0x05` | `GPIO_INTR_HIGH_LEVEL`                        |
| `ONLOW_WE`  | `0x0C` | `GPIO_INTR_LOW_LEVEL` en `gpio_wakeup_enable()`  |
| `ONHIGH_WE` | `0x0D` | `GPIO_INTR_HIGH_LEVEL` en `gpio_wakeup_enable()` |

### Een vlag in het ESP-IDF

Het tellen van drukken op een knop, rechtstreeks in het ESP-IDF:

```c
#include <stdbool.h>
#include <stdio.h>
#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

#define BUTTON_GPIO GPIO_NUM_25  // D2
#define LOOP_PERIOD_MS 10

static volatile bool is_button_pressed = false;  // flag: set by the ISR, cleared by the main loop
static volatile int press_count = 0;             // written by the ISR only

static void IRAM_ATTR count_press_isr(void *arg) {
  press_count++;
  is_button_pressed = true;
}

void app_main(void) {
  gpio_config_t button_config = {
    .pin_bit_mask = 1ULL << BUTTON_GPIO,
    .mode = GPIO_MODE_INPUT,
    .pull_up_en = GPIO_PULLUP_ENABLE,
    .pull_down_en = GPIO_PULLDOWN_DISABLE,
    .intr_type = GPIO_INTR_NEGEDGE,  // FALLING
  };
  ESP_ERROR_CHECK(gpio_config(&button_config));

  ESP_ERROR_CHECK(gpio_install_isr_service(0));  // once, for all GPIO interrupts
  ESP_ERROR_CHECK(gpio_isr_handler_add(BUTTON_GPIO, count_press_isr, NULL));

  while (1) {
    if (is_button_pressed) {
      is_button_pressed = false;
      printf("button pressed %d times\n", press_count);
    }
    vTaskDelay(pdMS_TO_TICKS(LOOP_PERIOD_MS));
  }
}
```

Wat opvalt:

- **Het interrupt-type staat in de configuratiestruct**, in het veld
  `.intr_type`. In [4.4.8](../4_gpio/4.4_digitale_input.md#448-onder-de-motorkap-het-esp-idf) stond daar nog `GPIO_INTR_DISABLE`.
- **`gpio_install_isr_service(0)`** gebeurt één keer, voor alle pinnen samen.
  Met de vlag `0` wachten de interrupts tijdens het schrijven naar het
  flashgeheugen, net zoals in de Arduino core (zie [7.3.4](./7.3_gpio_interrupts_in_de_arduino_core.md#arduino_isr_attr-en-iram_attr)). `IRAM_ATTR` is dan
  strikt genomen niet nodig, maar de voorbeelden van Espressif gebruiken het
  wel: de ISR start er sneller door.
- **De handler heeft altijd een `void *arg`.** Het derde argument van
  `gpio_isr_handler_add()` wordt aan de handler doorgegeven, zoals `arg` bij
  `attachInterruptArg()`. Hier is dat `NULL`: de handler gebruikt het niet.
- **`static`** voor de functie en de variabelen: ze zijn enkel zichtbaar in dit
  bestand (zie [A3.4](../appendix_3_static/appendix_3_static.md#a34-static-buiten-een-functie)).
- **De `while (1)`-lus controleert de vlag elke 10 ms**, en geeft met
  `vTaskDelay()` tussendoor de processor vrij, zoals in [A3.4.2](../appendix_3_static/appendix_3_static.md#a342-beide-betekenissen-samen-de-timer-in-het-esp-idf).

In het ESP-IDF wordt een melding van een ISR meestal niet met een vlag
doorgegeven, maar met een **queue** van FreeRTOS (`xQueueSendFromISR()`). Het
voorbeeld `generic_gpio` van Espressif doet dat: een taak wacht op de queue,
en wordt pas wakker wanneer de ISR er iets in plaatst. De lus hoeft dan niet
meer om de 10 ms te controleren. Dat is werk voor een RTOS, en komt later in
de opleiding aan bod (zie [7.1.5](./7.1_de_superloop.md#715-een-alternatief-een-rtos)).

[generic_gpio](https://github.com/espressif/esp-idf/tree/master/examples/peripherals/gpio/generic_gpio)*
