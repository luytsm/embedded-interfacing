# 5.7 Tekst zonder String

Doorheen dit hoofdstuk kwam tekst voortdurend terug: commando's uit de Serial
Monitor, NMEA-regels van een GPS-module, debugregels naar de computer. In geen
enkel voorbeeld werd daarvoor de klasse `String` gebruikt. Dat is geen toeval.
Deze sectie staat daar nog even bij stil, en sluit af met de functies uit
`string.h` die bij het werken met buffers het vaakst nodig zijn.

## 5.7.1 Reflectie: waarom geen String?

In [3.2.5](../3_c_en_cpp/3.2_datatypes.md#325-string-vermijden-char-en-stringh) stonden de nadelen van `String` al op een rij: geheugen op de heap,
fragmentatie, en een geheugengebruik dat niet voorspelbaar is. Seriële
communicatie is net de plaats waar die nadelen het zwaarst doorwegen:

- **Data blijft binnenkomen.** Een GPS-module stuurt elke seconde nieuwe
  regels, een gebruiker typt het ene commando na het andere. Met `String` en
  `+=` wordt bij elk ontvangen teken geheugen aangevraagd en vrijgegeven, en
  dat dagen aan een stuk.
- **De lengte ligt niet vast.** Een `String` groeit mee met wat er binnenkomt.
  Stuurt een module door een fout een regel zonder regeleinde, dan blijft de
  `String` groeien tot het geheugen op is. Een `char`-array heeft een vaste
  grootte, en de code beslist zelf wat er met tekens gebeurt die niet passen
  (zie [5.5.4](./5.5_serial_in_de_arduino_core.md#554-functies-die-wachten)).
- **De handige functies wachten.** `readString()` en `readStringUntil()`
  geven een `String` terug en blokkeren `loop()` tot een timeout (zie [5.5.4](./5.5_serial_in_de_arduino_core.md#554-functies-die-wachten)).
- **Het ESP-IDF kent geen String.** Dat is plain C (zie [5.5.6](./5.5_serial_in_de_arduino_core.md#556-onder-de-motorkap-het-esp-idf)). Code die met
  `char`-arrays en `string.h` werkt, gaat zonder aanpassingen mee naar het
  ESP-IDF of naar een andere microcontroller.
- **Seriële data zijn bytes.** De UART verstuurt bytes, en een `char`-array
  is precies dat: een rij bytes. Er zit geen extra laag tussen.

Twee vormen volstaan dus voor bijna alle tekst in een sketch, zoals al
samengevat in [3.4.3](../3_c_en_cpp/3.4_functies.md#343-pass-by-value-en-pass-by-reference):

| Nodig                                       | Gebruik                          | In plaats van           |
| ------------------------------------------- | -------------------------------- | ----------------------- |
| een buffer om in te schrijven of in te lezen | `char line_buffer[32];`          | `String line_buffer;`   |
| een vaste tekst                             | `const char *message = "ready";` | `String message = "ready";` |

> **Let op:** een string literal staat altijd tussen **dubbele** aanhalingstekens:
> `"ready"`. Enkele aanhalingstekens zijn voor één teken: `'r'` is een `char`
> met de ASCII-waarde 114 (zie [5.6.1](./5.6_tekst_en_bytes.md#561-ascii)), en `''` geeft een compilefout. Vergeet
> ook de `const` niet bij `const char *`: een string literal mag niet
> aangepast worden (zie [3.4.3](../3_c_en_cpp/3.4_functies.md#343-pass-by-value-en-pass-by-reference)).

Wat `String` gemakkelijk maakt, zoals `+` om tekst samen te voegen en `==` om
te vergelijken, bestaat voor `char`-arrays als functie in `string.h`. De rest
van deze sectie overloopt de vijf belangrijkste, elk met een eigen voorbeeld.
Alle voorbeelden veronderstellen `#include <string.h>`. In een Arduino-sketch
is die al ingeladen via `Arduino.h`, in het ESP-IDF moet ze er expliciet bij.

## 5.7.2 memcpy(): kopiëren tussen twee buffers

`memcpy(dst, src, n)` kopieert **exact `n` bytes** van `src` naar `dst`. De
functie kijkt niet naar de inhoud: een `'\0'` stopt het kopiëren niet. Dat
maakt ze geschikt voor zowel tekst als binaire data.

Een toepassing: de regelbuffer uit [5.5.4](./5.5_serial_in_de_arduino_core.md#554-functies-die-wachten) wordt meteen hergebruikt voor de
volgende regel. Moet het laatste geldige commando bewaard blijven, dan wordt
het naar een aparte buffer gekopieerd:

```cpp
const int LINE_BUFFER_SIZE = 32;

char line_buffer[LINE_BUFFER_SIZE];
int line_length = 0;
char last_command[LINE_BUFFER_SIZE];

void store_last_command() {
  // line_length characters plus the closing '\0'
  memcpy(last_command, line_buffer, line_length + 1);
}
```

Wat opvalt:

- Het aantal bytes is `line_length + 1`: zonder de `'\0'` is
  `last_command` geen geldige C-string.
- Beide buffers zijn even groot, dus wat in `line_buffer` past, past ook in
  `last_command`. Is de doelbuffer kleiner, dan schrijft `memcpy()` er
  zonder waarschuwing voorbij.
- De twee buffers mogen niet **overlappen**. Voor kopiëren binnen dezelfde
  buffer, bijvoorbeeld om tekst een plaats op te schuiven, bestaat
  `memmove()`.

## 5.7.3 memset(): een buffer leegmaken

`memset(dst, value, n)` vult `n` bytes met dezelfde waarde. Met de waarde `0`
wordt een buffer volledig leeggemaakt. Omdat `'\0'` de ASCII-waarde 0 heeft,
is elke byte daarna een afsluitend teken.

Een toepassing: na het verwerken van een regel de buffer leegmaken, zodat er
geen resten van een vorige, langere regel achterblijven:

```cpp
const int LINE_BUFFER_SIZE = 32;

char line_buffer[LINE_BUFFER_SIZE];
int line_length = 0;

void clear_line_buffer() {
  memset(line_buffer, 0, sizeof(line_buffer));
  line_length = 0;
}
```

Wat opvalt:

- `sizeof(line_buffer)` geeft hier 32, omdat `line_buffer` een array is.
  Binnen een functie die de buffer als parameter krijgt, geeft `sizeof` de
  grootte van een pointer (zie [3.4.3](../3_c_en_cpp/3.4_functies.md#343-pass-by-value-en-pass-by-reference)). Geef daar de grootte apart mee.
- Strikt genomen volstaat `line_buffer[0] = '\0'` om de tekst leeg te maken.
  `memset()` maakt echter de **volledige** buffer leeg, wat bij het debuggen
  helpt: in een uitgeprinte of bekeken buffer staan geen oude tekens meer.

## 5.7.4 strcat(): twee buffers samenvoegen

`strcat(dst, src)` plakt de tekst uit `src` achter de tekst die al in `dst`
staat. Het is de tegenhanger van `+=` bij een `String`.

Een toepassing: een antwoord opbouwen uit een vaste tekst en het ontvangen
commando:

```cpp
const int REPLY_BUFFER_SIZE = 48;

void send_unknown_command_reply(const char *command) {
  char reply[REPLY_BUFFER_SIZE] = "unknown command: ";

  // only append when the result, including '\0', fits in the buffer
  if (strlen(reply) + strlen(command) < sizeof(reply)) {
    strcat(reply, command);
  }

  Serial.println(reply);
}
```

Wat opvalt:

- `strcat()` zoekt de `'\0'` in `dst` en begint daar te schrijven. `dst` moet
  dus al een **geldige C-string** zijn. Een buffer die enkel gedeclareerd is,
  zoals `char reply[48];`, bevat willekeurige bytes, en dan schrijft
  `strcat()` op een willekeurige plaats. Initialiseer de buffer daarom met een
  tekst, of met `""`.
- `strcat()` controleert de grootte van `dst` niet. De controle met
  `strlen()` vooraf voorkomt een buffer overflow. `strncat()` en
  `snprintf()` zijn alternatieven met een ingebouwd maximum (zie [3.2.5](../3_c_en_cpp/3.2_datatypes.md#325-string-vermijden-char-en-stringh)).

## 5.7.5 strcmp(): twee buffers vergelijken

`strcmp(a, b)` vergelijkt twee teksten teken per teken, en geeft **0** terug
als ze gelijk zijn. Is de tekst verschillend, dan is het resultaat negatief of
positief, afhankelijk van welke tekst alfabetisch eerst komt.

Een toepassing: een ontvangen regel herkennen als commando:

```cpp
const uint8_t LED_PIN = 17;  // D10

void handle_command(const char *command) {
  if (strcmp(command, "on") == 0) {
    digitalWrite(LED_PIN, HIGH);
  } else if (strcmp(command, "off") == 0) {
    digitalWrite(LED_PIN, LOW);
  } else {
    Serial.print("unknown command: ");
    Serial.println(command);
  }
}
```

Wat opvalt:

- De voorwaarde is `== 0`. `if (strcmp(command, "on"))` zonder vergelijking
  is waar wanneer de teksten **verschillen**: precies omgekeerd van wat er
  bedoeld wordt.
- `command == "on"` compileert, maar vergelijkt twee **adressen** en niet de
  tekst (zie [3.4.3](../3_c_en_cpp/3.4_functies.md#343-pass-by-value-en-pass-by-reference)). Die vergelijking is zo goed als altijd onwaar.
- `strcmp()` is hoofdlettergevoelig: `"ON"` is niet gelijk aan `"on"`.

## 5.7.6 strlen(): hulp bij het verwerken van een buffer

`strlen(s)` telt het aantal tekens tot de eerste `'\0'`. De `'\0'` zelf telt
niet mee. Dat is iets anders dan `sizeof`, dat de grootte van de array geeft:

```cpp
char line_buffer[32] = "on";
// strlen(line_buffer) == 2: the length of the text
// sizeof(line_buffer) == 32: the size of the array
```

Een toepassing: voor een regel met `atoi()` omgezet wordt naar een getal,
controleren of ze enkel uit cijfers bestaat (zie [5.6.4](./5.6_tekst_en_bytes.md#564-van-teken-naar-getal)):

```cpp
bool is_number(const char *text) {
  size_t length = strlen(text);

  if (length == 0) {
    return false;  // an empty line is not a number
  }

  for (size_t i = 0; i < length; i++) {
    if (text[i] < '0' || text[i] > '9') {
      return false;
    }
  }

  return true;
}
```

Wat opvalt:

- `strlen()` wordt **één keer** opgeroepen, voor de lus. In de voorwaarde van
  de `for` zou `strlen()` bij elke doorloop opnieuw de volledige tekst
  aflopen.
- Het resultaat is van het type `size_t`, een type zonder teken dat groot
  genoeg is voor elke lengte. Daarom is ook de teller `i` een `size_t`.
- `strlen()` werkt enkel op een **geldige C-string**. Ontbreekt de `'\0'`,
  dan telt de functie verder in het geheugen na de buffer, tot ze ergens
  toevallig een 0 tegenkomt.
